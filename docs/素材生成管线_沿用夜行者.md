# 素材生成管线（沿用《夜行者》，适配 Roblox）

> 版本：2026-10-24
> 来源：`night-crawler`（《夜行者》，Unity）里已经实际跑通的生成管线，包括 `Nightwalker_Steam_V1.0/tools/`、`production/ch01/`，以及 `docs/Codex出图与秘塔H3接口调用说明20260927.md`。
> 原则：断链的图片、3D 和音频素材**优先沿用这套管线**。只有引擎相关的环节（导入、动画、音频格式）改成 Roblox 的做法。脚本移植时直接参考对方源码，不要另起炉灶。
> 分工：素材生成和视觉审查由主 agent 负责；移植脚本、写导入工具这类编码工作交给 subagent。

## 2. 必须照搬的纪律

1. **付费调用前先征得用户同意。** Codex 订阅额度、Ark、Meshy、ElevenLabs、秘塔都算付费。校验、干跑、上传都不算授权生成。脚本默认只干跑，要显式加 `--execute` 或类似参数才真正发请求。
2. **密钥只放在 `.env.local`。** 这个文件权限 0600，并且被 git 忽略。脚本只把密钥读进请求头，报错信息里要用 `scrub()` 把它替换掉。任何日志、JSON、Markdown、命令行参数里都不许出现密钥，也不要 `cat` 或 `echo` 它。
3. **一次调用只出一个产物。批次严格串行，失败就停，先报告，不要靠重试来补救。** Codex 每次调用都会改 `~/.codex/config.toml`，所以绝对不能并行。
4. **机械核验通过才算产出了候选。** Codex 通道要满足五条：哨兵回复正确（`IMAGE_TOOL_USED image_gen ./<NAME>.png`）、文件是真 PNG、SHA 与所有输入图都不同、在 `~/.codex/generated_images` 里能找到字节一致的原件、全局 config 还原到基线 SHA。agent 的自述不算证据。
5. **只新建，不覆盖。** 用 `cp -n`。已经出过图的提示词不再修改，返工就新开一个 `<ID>r2`。
6. **提示词由脚本生成，不手改。** 夜行者用的是 `make_prompts.py`。参考图要写明"只取风格，不取版式"。多张参考图时，image1 是唯一的身份权威，其余几张只作风格或材质标尺。不带参考图的纯文字生成保不住身份，禁止用于角色。
7. **每次调用都留记录。**
   - `generation_log.tsv`：一次调用一行，列为 time、id、status、output、output_sha256、size、prompt_sha256、refs、tokens、workdir。
   - `records/<ID>/`：存提示词全文、输入 SHA、末条消息和 meta。`/tmp` 工作目录会被清理，所以要在这里另存一份。
   - `job.json`：Ark、Meshy、ElevenLabs 各一份，记录请求参数、task id、积分或字符消耗、产物 SHA。
8. **状态机与审查。** 状态依次为 `planned` → `candidate_pending_review`（机械核验通过）→ `agent_reviewed` 或 `rejected` → `user_accepted`。
   - 生成素材的 agent 不能自己宣布通过。
   - `user_accepted` 只能由用户给出。
   - 审查结论记在 `review.tsv`。
9. **素材台账。** `asset_register_<批次>.csv` 由 `register_assets.py` 生成，列沿用夜行者：asset_id、asset_type、source_type、provider_model_version、prompt_record_path、license_*、commercial_use_verified、ai_generated、generation_job_id、original_sha256、derived_from、triangles、texture_size、import_test、visual_review、approval_status、notes。许可和商用核查没做完之前，素材不算 approved。
10. **任务清单。** 每一批素材写一份 `TASKLIST_*.md`，说明范围、不在范围内的东西、通道、批次和 ID 表。完成后写 `REVIEW_*.md`。

## 3. Roblox 适配

### 3.1 目录

```
art/
  concepts/      概念图、风格锚点（anchors/），已经过审查的候选
  references/    风格参考 S、光影参考 L
  source-blender/ .blend 源文件和 Blender 脚本
  vfx/           特效贴图源文件
  exports/       可以导入 Roblox 的成品：FBX/OBJ、PNG、OGG
production/<批次>/
  TASKLIST_*.md  REVIEW_*.md  generation_log.tsv  review.tsv  asset_register_*.csv
  prompts/  records/  raw/（不进 git）  job.json
tools/           移植过来的生成脚本，路径改成指向本仓库
```

### 3.2 图片

- Roblox 上传后会把图片缩到最大 1024×1024。贴图在出图时就按 1024 或 512 规划；Codex 出的 1672×941 先裁切再缩放。
- 素材要符合视觉圣经 V1.1 的 Token 和公开状态色。审查时先对照视觉圣经，再看实机截图。
- 贴图、贴花、UI 图片的导入方式：Studio 的 Asset Manager 或 Open Cloud Assets API 上传，得到 `rbxassetid://`，然后把 ID 写进 Rojo 管理的配置文件，不要只改场景。

### 3.3 3D 与动画

- Meshy 产出的 FBX/GLB 用 Studio 3D Importer 导入，或者走 Open Cloud 上传。**单个 MeshPart 的面数上限以官方文档为准**，面数目标沿用夜行者 `POLY` 表的量级（道具 2k—6k）。PBR 材质用 `SurfaceAppearance`。
- 角色：按 D6 决策，玩家角色用玩家自己的头像加外观叠加层，**不做自定义角色模型**。所以 Meshy 角色、Mixamo 绑定、Mixamo 动作包在断链里都是**低优先级**。
  - 丧尸的外观附件（头罩、骨刺这一类）走 Meshy 道具通道，做成 R15 的 Accessory 或 WeldConstraint 挂件。
  - 需要特殊动作（扑咬、治愈注射）时，在 Studio Animation Editor 里对着 R15 做，或者用 Blender 重定向到 R15 再导入。Mixamo 骨架不能直接用在 R15 上。
- 导入后的模型放进 `src/assets`（对应 `ServerStorage.GameAssets`），以 `.rbxm` 形式受 Rojo 管理。

### 3.4 音频

- ElevenLabs、MiniMax、ACE-Step 的产物先用 ffmpeg 处理：单声道或立体声、裁到玩法需要的长度、加淡出。响度沿用夜行者 `audio_to_unity.py` 的标准：音效峰值 −1 dBFS，环境音 −20 LUFS，音乐 −16 LUFS 且 true peak ≤ −1.5 dBTP。然后导出 OGG 或 MP3。
- 上传 Roblox 音频有配额、时长和审核限制，第一次上传前要按官方文档核实一遍。音频 ID 写进 `src/shared` 里的音效表，SoundId 命名与代码中的枚举一致。
- 和夜行者一样，每个 SoundId 保留多条变体，运行时随机播放，避免听感重复。

### 3.5 审计

- 夜行者用 `look_audit` 和 `screen_audit` 做实机截图对比。断链改为通过 Studio MCP 截图，然后对照视觉圣经和目标画面，由主 agent 做视觉审查。

## 4. 起步清单

1. 在本仓库建 `.env.local`（权限 0600，已加入 `.gitignore`）。密钥由用户自己填，agent 不复制、不读取别的项目的密钥值。
2. 把 `codex_img.sh`、`run_batch.sh`、`ark_env_images.py`、`meshy_lib.py`、`elevenlabs_sfx.py` 移植到 `tools/`。只改路径、ID 前缀（`btc-`）和日志位置。这一步派给 subagent，主 agent 审查。
3. 先跑一次 Codex 额度探针（夜行者文档第一部分第 7 节）。通过之后，出断链的风格基准 S 和光影基准 L，交给用户验收。
4. 定下基准之后，按 Gate A 灰盒的需要分批出素材。Gate A0 纯追逐原型用灰盒，不需要正式素材。
