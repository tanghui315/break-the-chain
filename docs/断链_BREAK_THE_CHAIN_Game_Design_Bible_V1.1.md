# 《断链》BREAK THE CHAIN
## Game Design Bible V1.1｜完整玩法与系统设计圣经

> **项目代号**：BREAK THE CHAIN /《断链》  
> **文档版本**：V1.1（可执行设计基线，尚未经过真实玩家验证；V1.0 → V1.1 变更见 §0.4）  
> **编制日期**：2026-10-24  
> **目标平台**：Roblox（PC + 手机横屏优先；平板兼容）  
> **开发栈**：Roblox Studio / Luau / Rojo / Git / Codex 或 Claude  
> **核心模式**：多人短局，动态人类—丧尸阵营转换，感染树争夺与连锁逆转  
> **对局规模**：**最少 4 人可以开局，单局最多 24 人**；1～3 名真人时由 Bot 补位进行练习局，不进入正式结算（D4）

> **文档用途**：交付给策划、程序、AI Coding Agent、关卡、美术、QA，用于制作第一版可玩的 Roblox 游戏。

# 0. 阅读须知与决策约定

本文件以**能够开发、能够测试、能够修改**为优先级，不是宣传文案；文中数字均为**建议的首次实验参数**，并非已经验证的最佳平衡值。不要把它们说成 Roblox 官方要求或行业平均值。

## 0.1 决策层级

| 标识 | 含义 | 执行要求 |
|---|---|---|
| `LOCKED` | 用户已经确认或首版不可妥协的设计方向 | 未经产品负责人批准不得更改 |
| `BASELINE` | 当前版本暂定的默认实现 | 必须实现为可配置项，允许经过测试改动 |
| `EXPERIMENT` | 仅用于实验或 A/B 的想法 | 不得未经验证加入 P0 正式玩法 |
| `FUTURE` | 后续候选功能 | 首版不做 |

## 0.2 已锁定设计（LOCKED）

1. 游戏名暂用《断链》/ BREAK THE CHAIN。
2. 核心玩法为**开始时所有玩家都是人类；出现被感染者后，人类和丧尸玩家实时对抗**。
3. **玩家被咬后不会退出对局，而是转换阵营**；丧尸目标是感染所有未撤离的人类。
4. 感染记录玩家间的传播父子关系，形成**可断裂的感染树**。
5. 人类可以治愈非零号关键感染者，触发下游分支断联；丧尸可以争取重连。
6. **人数不足也能开局，单局最多 24 人**。不能依赖“必须凑满 24 人”才能玩。
7. 目标是短局、多人参与、能连续重开，不将首版做成大型开放世界求生。
8. 与视觉圣经一致：风格化半写实、非血腥、状态清晰、手机可读、24 人压力预算。

# 1. 游戏是什么——一页产品定义

## 1.1 一句话 Pitch

**一群人试图逃离被感染的城市；被咬的队友会变成丧尸，但只要救回关键感染者，就可能让一整条尸群感染链瓦解。**

推广文案候选：

- 中文：**“你感染了一队人？我救回一个，整队都可能倒戈。”**
- 英文：**“Infect the squad. Break the chain. Turn the match around.”**

禁止将宣传描述为“自由 AI 丧尸学习”“开放世界末日生存”“几百人大逃杀”——这些不属于首版能力。

## 1.2 类型与玩家承诺

- **主品类**：多人生存追逐 / Infection PvP / 轻射击对抗 / 轻度阵营策略（D10）。
- **体验关键词**：朋友变敌人、局势突然反转、短局追逐、营救关键人物、感染关系博弈。
- **每分钟行为**：移动、搜索路线、追击/规避、射击击倒、近战打断、协作、扫描、抢解药、扑咬、救治、断联、重连、撤离。
- **单局内进展**：人类人数下降→感染网络扩张→重点节点出现→断链→争夺重连→终局撤离。
- **局外进展**：角色外观、称号、档案、战绩、非战力性的表现收集。

## 1.3 四个设计支柱

| 支柱 | 玩家感受 | 判断标准 |
|---|---|---|
| `FAST` 快速进入冲突 | 不等很久就能跑、咬、救人 | 第一局 ≤90 秒应出现感染或救援事件 |
| `REVERSAL` 阵营反转 | 人类、丧尸都有翻盘空间 | 断链和重连可以改变对局的胜负走势 |
| `AGENCY` 双方自主性 | 被感染不是淘汰，断联也不是被控制看动画 | 各状态都有实时可做的操作和选择 |
| `READABLE` 一眼看懂 | 手机端追逐时也懂自己和别人的公开状态 | 玩家不必研究完整图论才能玩懂 |

## 1.4 明确不做

- 不做对战属性付费、装备碾压、永久攻击力升级。
- 不做首版 50～100 人单局；不依赖超大 NPC 尸潮。
- 不做复杂枪械弹道、武器改装、配件和几十种枪械；不做玩家永久死亡。只做 §9A 的轻量命中扫描武器；玩家丧尸被打死后以原感染身份复活（D10）。
- 不做无限刷材料、饥饿值、烹饪、开放世界采集、长线盖基地。
- 不做让丧尸实际在线学习玩家动作的大模型 AI。
- 不做初期 6 种职业、15 种丧尸类型、多张付费地图。
- 不做局内必需语音交流；不开启语音的玩家应能完整游玩。

# 2. 目标玩家、产品定位与竞争差异

## 2.1 目标玩家

**主目标**：喜欢 Roblox 多人轻竞技、恐怖但不过度血腥、朋友一起玩的手机/PC 玩家。年龄与可触达群体最终取决于 Roblox 正式的内容成熟度标注和发布资格。

**首发市场与语言（D9）**：中国大陆没有官方运营的 Roblox，主要玩家在北美、拉美、东南亚和欧洲。商店页、缩略图文案和局内 UI **以英文为主**，接入 Roblox 自动翻译与 LocalizationTable；中文是本地化语言之一。见 §17.5。

**玩家画像（设计假设）**：

1. **独自加入玩家**：必须一局内快速找到目标，不依赖认识队友。
2. **2～4 人好友小队**：重视一起跑、一起救、互相感染的搞笑与紧张。
3. **连续刷局玩家**：愿意为“再翻一次盘”连续玩 2～3 局。
4. **短视频观众**：看懂“红色感染队伍突然断链变黄，然后部分变绿”的高光。

## 2.2 与成熟 Infection 模式的主要差别

普通 Infection 模式的状态往往单向累积：`人类 -> 感染者`。本项目的核心创新**组合**是：

```text
普通玩法：人类 --被咬--> 丧尸（基本不可逆）
《断链》：人类 --被咬--> 尸变过渡 --5秒--> 稳定丧尸
                         ^                         |
                         |      关键节点被治愈      |
                   恢复人类 <-- 断联8秒 <-- 子树断裂
                                      |
                                      +-- 接触稳定丧尸并重连 --> 稳定丧尸
```

我们不声称“阵营感染”“伪装感染”“治愈”分别属于全球原创。**真正待验证的差异化是：感染关系本身成为攻防资源。**

## 2.3 原型通过标准

仅制作感染树并不代表好玩。首版至少需要证明：

- **基本追逐好玩**：不使用断链时，移动、追逐、闪躲已有乐趣。
- **断链值得争夺**：玩家会主动寻找枢纽、保护节点，而非随机使用解药。
- **重连有真实选择**：断联者感到紧张但不无助，救人和救链带来新互动。
- **局势仍可理解**：看不懂树的新人也能跟着 UI 指引完成目标。

# 3. 三层核心循环（Core Loops）

## 3.1 秒级：操作反馈（3～15 秒）

| 人类循环 | 丧尸循环 |
|---|---|
| 找掩体 / 看见感染者 → 冲刺或转向 → 拉开距离 → 寻找治疗/撤离机会 | 侦察路线 → 预判人类逃跑方向 → 突袭扑咬 → 建立感染分支 → 转而追下一个目标 |
| 人类获得扫描后 → 评估枢纽 → 集结 → 击退护卫 → 注射 | 丧尸发现本分支有危险 → 护送枢纽 → 拦截治疗者 → 断联后争取重连 |

## 3.2 局级：感染—断链—撤离（6～8 分钟）

```mermaid
flowchart LR
  A[全人类准备] --> B[初始感染事件]
  B --> C[感染树扩张]
  C --> D[扫描并争夺枢纽]
  D --> E[断链与重连]
  E --> C
  E --> F[终局撤离]
  F --> G{结果}
  G --> H[人类成功撤离 / 清除感染]
  G --> I[丧尸感染全部人类 / 阻止撤离]
```

## 3.3 局外：邀请—再来一局—成长

```text
看到精彩瞬间 / 被朋友邀请
    ↓
无需额外付费进入 → 4 人可开局
    ↓
体验一次被感染或断链翻盘
    ↓
结算展示“我感染了谁 / 哪条链被切断”
    ↓
领取非战力的外观进度 / 每日挑战
    ↓
与朋友重开 / 分享本局精彩事件
```

> 局外成长不增加局内属性，否则新增玩家难以公平进入短局竞技。

# 4. 一局的生命周期与节奏

## 4.1 正式局状态机

| 状态 | 触发 | 玩家可做的事 | 退出条件 |
|---|---|---|---|
| `WAITING` 等待大厅 | 玩家进入 Place | 邀友、练习操作、选择外观 | 有 ≥1 名真人且倒计时完成；真人 <4 时由 Bot 补位为练习局（§5.2） |
| `PREPARE` 准备期 | 匹配成功 | 所有人类移动、认路、熟悉交互 | 20 秒到期 |
| `OUTBREAK` 爆发期 | 公开“隔离突破”事件（§6.1） | 闪避、追击、首个玩家尸变 | 所有零号均已建立 |
| `CONTEST` 链争夺 | 首位玩家感染后 | 扩散感染、扫描、治愈、断链、重连、修复撤离设施 | 进入最后 90 秒 |
| `EXTRACTION` 撤离 | 剩余时间≤90 秒 | 人类冲出口、丧尸阻截 | 达成胜负条件或倒计时归零 |
| `RESULT` 结算 | 服务端发出唯一最终判定 | 看本局感染树复盘与奖励 | 结算倒计时结束、进入下一局 |

**重要**：游戏阶段与玩家状态分离。`INCUBATING` 是玩家状态，不是新的整局阶段；某名玩家在任何阶段被感染，都会经过短暂的公开尸变过渡。

## 4.2 7 分钟中型局示例

| 时间点 | 设计事件 | 情绪目标 |
|---|---|---|
| 0:00～0:20 | 所有人类分散探索，广播宣告感染事故 | 有一点准备时间，但不冗长 |
| 0:20～1:00 | “隔离突破”事件公开选出零号，经 5 秒公开尸变后开始感染他人 | “刚才的队友变了” |
| 1:00～2:30 | 丧尸感染更多人，修复设施与解药争夺开始 | 紧迫感提高 |
| 2:30～5:30 | 人类扫描枢纽并发起救治，丧尸组织保护和重连 | 反复翻盘、形成战术 |
| 5:30～7:00 | 撤离窗口开启，围堵、牺牲与营救 | 高潮与清晰收尾 |
| 7:00 后 | 结果、传播树、短暂结算、快速重赛 | 愿意再玩一局 |

各阶段不强制等到预定时间才允许感染或治愈；这些是节奏目标，而非固定剧本。必须由服务器权威计时。

# 5. 动态人数与开局规则（4～24 人）

## 5.1 设计目标

**人数少也能玩、人数多更热闹**。不能因为并发不足让大厅一直空等；也不能把 24 人场景强塞给 4 个人追逐。

| 开局时真人数 N | 最大正式对局时间 | 初始零号感染源 | 需激活的撤离电力节点 | 人类撤离胜利人数 | 地图范围 |
|---:|---:|---:|---:|---:|---|
| 1～3 名真人（练习局） | 6 分钟（Bot 补位至 6 名参与者） | 1 | 1 | 1 人，不计正式战绩 | 医院 + 中央街口 + 地铁入口 |
| **4～7** | **6 分钟** | **1** | **1** | **1 人** | 医院 + 中央街口 + 地铁入口 |
| **8～15** | **7 分钟** | **1** | **2** | **2 人** | 增加庭院 / 控制室 |
| **16～24** | **8 分钟** | **2** | **3** | **4 人** | 增加停车楼 / 侧街 / 地铁连廊 |

注意：初始零号感染源数代表**最终可能出现的独立感染根**；不是开局就有丧尸玩家。所有玩家在 PREPARE 期确实都是人类。人数档按开局时的**参与者总数**（真人 + Bot）确定。

**人数档与断链（D8）**：4～7 人档在数学上几乎不会出现“关键枢纽”（模拟见评估文档 §3.2，本文 §8.7），这一档是“经典感染 + 小规模治愈”体验；**断链是 8 人以上的特色**。核心玩法验证与宣传素材录制都以 8 人以上（建议 12 人以上）的对局为准。

## 5.2 等待与新玩家加入

- 大厅中有 ≥1 名真人时开始 30 秒开局倒计时；等待期继续吸纳新玩家，最多 24 人。
- **Bot 补位（D4）**：开局时真人为 1～3 名，则用 Bot 补足到 `BotFillTarget`（6）名参与者进行**练习局**：规则与 4～7 档相同，但不产生正式战绩、排行榜、每周挑战进度或持久奖励，结算页明确标注 Bot。真人 ≥4 名时为正式局，**不补 Bot**。Bot 只在开局时加入，绝不在对局中途回填。
- 满 24 人可提前启动；不能为了人数规模而牺牲足够的准备与加载时间。
- **中途加入（D5）**：
  - 开局后 `LateJoinHumanWindowSeconds`（60）秒内加入 → 以 `HUMAN` 进入本局，获得 7 秒防感染保护；本局冻结的人数档参数不变。
  - 60 秒后、撤离期之前加入 → 以 `INFECTED` 叶子身份挂到一棵仍存在的感染树的根（或 `VirtualRoot`）下，在丧尸出生点生成；其感染他人不计展示分（防止中途进服刷分），其余规则与普通丧尸相同。
  - 撤离期（最后 90 秒）加入 → 有限观战（只看公开信息），结算后进入下一局。
  - 中途加入者不计入 `RoundInitialPlayerCount`，不改变撤离目标。与原“隔离区等待下一局”方案做 A/B（EXP-07）。
- 玩家可在大厅主动“下一局继续”；不强制每局离开服务器。
- 首版可使用 Roblox 默认匹配与一个持续运行的单 Place 回合循环；后期再评估分离大厅 / Match Place 与专门队伍匹配。

## 5.3 人数缩放的地图规则

- 小局使用可见、符合世界观的封锁门和坍塌路障关闭侧区，而不是突然出现透明空气墙。
- 不因地图缩小改变位置、碰撞箱和战斗基本规则；只改变开放路线和任务点数量。
- 医院、中央街口、地铁出口始终是固定地标；新手在不同规模局中不会迷路。
- 目标是让玩家在 15～30 秒内有机会再次遇见对手，不能全图寻找半分钟还没有交互。

## 5.4 人数变化不即时改变本局规则

对局启动时冻结 `RoundInitialPlayerCount`、地图开放区、电力节点数、时长与撤离目标数，不因为有人临时退出就实时改变地图，防止动态封路卡住玩家。人数过少时允许提早结束；对局中途绝不用 Bot 回填，中途加入的真人按 §5.2 规则进入。

**人数退出防锁死**：如果初始撤离目标大于尚有资格撤离的人数，且离局者已无法回归，此局进入一次性“撤离目标可达性修正”：目标降至 `max(1, min(原目标, 当前仍在局内的人类及可恢复丧尸的理论人数))`，并公开提示；每局最多执行一次。若已经无人能够成为人类，则依正常丧尸获胜规则结束。该修正需要单元测试防止刷退局影响胜负与奖励。

# 6. 零号感染源：所有玩家先是人类

## 6.1 首版感染起点（V1.1 BASELINE：公开隔离突破，D7）

玩家初始均为 `HUMAN`。PREPARE 结束前 3 秒，服务端广播“隔离突破”预警；进入 OUTBREAK 时，**公开**选出 `seedCount` 名参与者成为零号感染者。

- **选择规则**：候选为仍在场、可达、不处于保护状态的参与者；优先选择本服务器上一局未当过零号的参与者；**不按技术、战绩或付费选择**（理由见 §8.7）；两个根时选不同参与者。
- **表现**：被选中者原地播放公开的扑击/尸变表现，进入 5 秒公开尸变过渡后成为 `INFECTED`（`isRoot = true`）。本人收到明确提示“你是零号源头”，全场收到“隔离突破”公告。
- **不是暗箱操作**：选择规则写在新手说明里；不会把玩家暗中改阵营再假装是玩家失误。
- **失败处理**：若被选中者在尸变过渡中离开，重新选择一次；仍失败则本局按“感染未爆发，人类存活”的短局结果结束并记录异常，不无限等待。

**NPC 版本（EXPERIMENT，EXP-06，Gate B 之后评估）**：场景内释放 1～`MaxOutbreakNPCs` 只事件 NPC，首个有效扑咬建立零号根；根建立后 NPC 退出主战区；40 秒内没有有效感染时，回落到上面的隔离突破流程。NPC 版代入感更强，但开局时长不可控，还需要寻路与 AI 工作量，因此不进入 P0。不要为此实现复杂 NPC 学习系统。

## 6.2 零号玩家感染者的特殊规则

1. 拥有永久 `isRoot = true` 标识，是当前感染树根。
2. **不可用普通解药治愈**；扫描结果明确标识“零号源头 / 不可治愈”。
3. 可以感染人类、成为其他丧尸的重连目标。
4. 若有两名零号源头，各自成为不同树的根，其他感染者仍可通过重连从一棵树迁移到另一棵树。
5. 为避免零号过强，根节点不额外获得永久攻击力、免费隐身或无限突进。
6. **零号平衡杠杆（D2）**：零号扑咬冷却为普通值 × `RootBiteCooldownMultiplier`（1.5）；断联者以零号为重连目标时，读条为普通值 × `RootRelinkHoldMultiplier`（1.5）。目的是把感染工作推给子节点，形成可治愈的枢纽（§8.7）。
7. **开局保护（V1.1 补充 2，基于 8 人 Bot 实测）**：零号是公开靶子且开局唯一的丧尸，实测平均每局被打死约 5 次、首次感染中位 86 秒，未达 §9A.5“开局 60 秒内完成首次感染”。因此零号尸变完成后 `RootOutbreakProtectionSeconds`（15 秒）内**不受伤害**（击退、电击照常，头顶显示 PROTECTED）；零号死亡等待为人数档复活时间 × `RootRespawnMultiplier`（0.5）。两者都不增加零号的攻击能力，只让他能回到战场。

## 6.3 根节点退出游戏

- **根节点有后代**：服务器保留该感染树的虚拟源头 `VirtualRoot(seedId)`，其直接子节点仍为稳定感染者并保留后代关系。虚拟源头**不是一个可以被玩家触碰或治疗的实体**，也不会自动增强子节点；退出并不引发一场免费治愈。
- **根节点没有后代**：如果场上还有其他感染树则照常继续；否则视为感染源消失，进入 5 秒“是否还有尸变过渡者/断联感染者”的复核，若确实没有则人类获得**遏制成功**胜利。
- 不把任意普通玩家临时升级为“无敌零号”，避免强制改变其可治愈性。

## 6.4 母巢指挥（EXPERIMENT，EXP-09）

**定位**：零号不当“打手”，当“指挥官”。§6.2 第 5、6 条不变——零号仍无额外攻击力、隐身或突进，扑咬冷却仍 ×1.5、生命值仍 ×1.25。新增的能力**只增强仍连在本树上的丧尸**，并且全部带明显预兆。默认关闭（`HiveAbilitiesEnabled = false`），A/B 达标后才进入正式玩法。

**核心创新：指令沿感染树传递。** 只有 `rootId` 等于该零号、且当前稳定（不处于 `UNSTABLE` 断联）的丧尸能收到母巢指令。人类治愈枢纽造成断链时，下游分支同时失去母巢指挥——断链除了改变阵营，还削弱丧尸的协同。两名零号各自只指挥自己的树。`VirtualRoot` 不是实体，不拥有母巢能力（§6.3）。

1. **源头标记（主动）**
   - 零号在 `RootMarkRange`（60 studs）内、地图几何视线畅通时，对一名 `HUMAN` / `INCUBATING` 参与者使用。
   - 本树所有稳定丧尸在 `RootMarkSeconds`（6 秒）内隔墙看到该目标的轮廓；冷却 `RootMarkCooldownSeconds`（30 秒）。
   - 被标记者立即收到“你被源头盯上了”提示（反制：找掩体、拉开距离、靠近持枪队友）。
   - 只发送给被标记者与收到指令的丧尸，不全场广播（§17.6 泄密面：丧尸只能据此知道自己仍在树上）。
2. **母巢集结（主动）**
   - 零号原地引导 `RootRallyChannelSeconds`（2 秒）；引导中被电击、倒地、擒抱目标被打断则失败并进入短冷却（10 秒）。
   - 成功后在原地立起全场可见的“母巢信标”，持续 `RootRallyBeaconSeconds`（20 秒），冷却 `RootRallyCooldownSeconds`（60 秒）。
   - 信标存在期间，本树稳定丧尸复活时改为在信标处复活（仍走正常死亡时长与复活保护，不缩短死亡时间）。
   - 立起条件：最近人类距离 ≥ `RootRallyMinHumanDistance`（30 studs）；撤离开启后，距撤离区 ≥ `RespawnMinDistanceFromExtraction`。不满足时拒绝并提示原因。
   - 零号倒地或死亡时信标立即熄灭（反制：集中火力打倒零号来“拆信标”）。
3. **护主警报（被动，第二批实现）**：零号被击倒或擒抱人类时，30 studs 内本树稳定丧尸获得“源头遇袭”提示与 4 秒 +15% 移速。不做减伤光环。

**平衡护栏**
- 不改变零号个人战斗数值；所有收益随断链减少，形成天然负反馈。
- 技能覆盖时间合计 ≤ 30%：标记 6/30 秒，信标 20/60 秒。
- 新手说明写明三项能力及反制；瞄准零号仍提示“源头不可治愈”。

**A/B 验收（Bot 8 人局，同地图同版本，各 ≥ 20 局）**
- 人类胜率保持在 35%～65%（§25 A0.5）。
- MEDIUM 图平均遭遇间隔（`encounter_sample.avgGap`）明显缩短；标记后 10 秒内被咬的转化率可观测。
- `tree_shape_snapshot` 不出现星形化（枢纽率不高于 A 组）。
- 未达标则回到 A（关闭），不为过关调高零号个人能力。

# 7. 玩家身份与状态机

## 7.1 六个互斥主状态

| 状态 | 真实阵营 | 对他人外观 | 核心操作 | 能否成为救治目标 |
|---|---|---|---|---|
| `HUMAN` | 人类 | 人类 | 逃跑、近战/射击/电击（§9A）、扫描、解药、修复、撤离 | 不需要 |
| `INCUBATING`（显示为“尸变中”） | 感染阵营（V1.1 起公开） | 公开的半异化尸变过渡外观 | 移动；不能攻击/治疗/修复/撤离 | 不能直接注射；上游被治愈时立即恢复 |
| `INFECTED` | 丧尸 | 公开丧尸 | 追逐、扑咬（擒抱）、打断、护链、重连援助；可被打到倒地、死亡后复活（§9A.3） | **非根节点可以被治愈**（含倒地中，不含死亡中） |
| `UNSTABLE` | 丧尸但不稳定 | 金色断联外观 | 移动、逃离治疗者、向稳定感染者重连 | 不重复使用解药；计时到期自动恢复 |
| `EXTRACTED` | 已撤离人类 | 不在战场 | 结算等待、有限观战 | 不可作用 |
| `SPECTATOR` | 不属于当前正式局 | 不在战场 | 训练区等待 / 观看公开事件 | 不可作用 |

本地 HUD、角色状态、权限由服务端权威定义；显示特效遵循视觉圣经的 `VFX_REVEAL`、`VFX_CHAIN_CUT`、`VFX_UNSTABLE`、`VFX_CURE` 等约定。

## 7.2 核心转移

```mermaid
stateDiagram-v2
    [*] --> HUMAN
    HUMAN --> INCUBATING: 服务端确认扑咬
    INCUBATING --> INFECTED: 5秒尸变过渡结束
    INCUBATING --> HUMAN: 上游被治愈，过渡取消
    INFECTED --> HUMAN: 非根节点被直接治愈
    INFECTED --> UNSTABLE: 上游感染链接被切断
    UNSTABLE --> INFECTED: 在8秒内成功重连
    UNSTABLE --> HUMAN: 8秒到期且仍未重连
    HUMAN --> EXTRACTED: 满足撤离条件
    HUMAN --> SPECTATOR: 退出本局/离开
    INFECTED --> SPECTATOR: 退出本局/离开
```

`ROOT` 是 `INFECTED` 上的不可治愈标签，不单列主状态；`CURE_IMMUNITY` 是 `HUMAN` 的定时效果，不新增状态。`DOWNED`（倒地）、`DEAD`（死亡等待复活）、`STUNNED`（电击）、`CONTROL_IMMUNITY` 是丧尸身上的战斗生命状态或定时效果，`GRABBED` / `GRABBING` 是擒抱双方的定时效果（§9A），都不新增主状态。

## 7.3 尸变过渡（V1.1：公开，D1）

V1.0 的“潜伏保密”在实际中无法成立：扑咬动作与 `VFX_BITE` 对附近所有人可见，持有者被感染时解药掉落、交互失败也会暴露身份，Roblox 引擎默认复制的 Team、Attributes、Humanoid 属性还会额外泄露。因此 V1.1 把潜伏改为**公开的尸变过渡**：

- 被咬瞬间，本人收到 `你已感染：5 秒后完成尸变` 与倒计时；其他玩家看到公开的半异化外观和 `尸变中 / TURNING` 标识。
- 过渡期间可以移动，但不能扑咬、治疗、修复、拾取或使用解药、进入撤离判定。已持有的解药在过渡结束时掉落（§10.1）。
- 过渡者是感染树叶子；若其上游在过渡期间被治愈，过渡立即取消并恢复 `HUMAN`（播放 `VFX_CURE`，获得治愈保护）。
- 过渡结束成为 `INFECTED`，播放 `VFX_REVEAL`。

**仍然保密的信息**：感染树拓扑（谁是谁的上游/下游）、扫描结果、断联者的重连目标提示。权限规则见 §17.2，泄露仍属于 release blocker。

**实验（EXP-01b）**：`IncubationSecret=true` 的完整保密版本，须在 Gate B 核心玩法成立后、配合引擎层泄密审计再验证；没有 A/B 证据前不得进入 P0。

## 7.4 转换时允许与禁止的操作

- 转换时清除原阵营专属道具的可用性，不允许保留“人类解药 + 丧尸扑咬”。
- 原地以安全姿态完成表现，短暂无碰撞锁，避免角色被重置或穿墙。
- 阵营变化后不强制 Respawn / Teleport 到远处；尽可能保持动作连续性。
- 被治疗的玩家恢复人类后获得 7 秒防再次感染保护，不能马上遭到“无限互转”。
- 开局、治愈或断联转换不得重置其他玩家的冷却、获得无限资源或刷新排行榜奖励。

# 8. 感染树：全游戏最关键的数据模型

## 8.1 定义

每个正式局由 1～2 棵有向感染树构成；一个节点代表**某次仍有效的玩家感染身份**。每个非根感染者在当前稳定链上**最多有一个父节点**。父节点代表“最近一次使其进入或稳定留在感染阵营的感染来源”。

```text
零号 A [ROOT / 不可治愈]
├─ B [非根，可治愈]
│  ├─ D
│  └─ E
└─ C [非根，可治愈]
   ├─ F
   └─ G

若人类治愈 B：
A 保持感染；B 立刻恢复人类；D、E 进入 8 秒断联。
D、E 可各自寻找稳定感染者，或让其中一名先重连并带动自己仍附属的分支。
```

## 8.2 不变量（实现必须满足）

1. **无环**：任何节点都不能成为自身的祖先；所有有效稳定关系构成森林（多棵树）。
2. **唯一身份**：每名玩家在一局内只有一个有效状态；禁止既是 HUMAN 又是 INFECTED。
3. **至多一个父**：一个非根感染节点仅能有一个当前父节点；父子关系双向索引一致。
4. **不跨局继承**：每局生成独立 `roundId`；上局感染链不能污染下一局。
5. **源头受控**：真实或虚拟零号源头不可普通治愈；非根感染者都允许按规则被治愈。
6. **服务端唯一写入**：客户端不能指定自己的 `parentId`、`rootId`、`state` 或 `subtreeSize`。
7. **事件原子性**：感染、治愈、切断、重连与退出同一个服务器事件队列串行提交，不能生成两个父节点或同一玩家重复奖励。
8. **身份重置安全**：治愈后重新被咬，会获得新的 `infectionEpisodeId`；旧关系与旧计时器必须失效。
9. **尸变过渡节点是叶子**：`INCUBATING` 不能感染其他玩家，因此不会拥有有效感染后代。
10. **断联节点不能扩散**：`UNSTABLE` 状态不能感染新的人类，避免断链规则被绕开。

## 8.3 子树规模与战术价值

- `descendantCount(node)`：该节点当前仍有效的**后代数量**，不包含自己。
- `branchImpact(node) = 1 + descendantCount(node)`：救回它可能直接影响的总人数（包括目标）。
- 实际救回人数通常低于 `branchImpact`：因为后代还有 **8 秒**重连机会。
- **重要**：人类扫描 UI 不直接展示全球精确树，只显示近距离目标的简化等级（见第 12 章）。

## 8.4 三种不同的图变化

| 事件 | 当前节点 | 对子节点和后代 | 战术结果 |
|---|---|---|---|
| `BITE` 稳定感染者咬到人类 | 新增一片尸变过渡叶子，5 秒后成为稳定感染者 | 不影响其他节点 | 传播范围扩大 |
| `CURE` 人类治愈非根 B | B 立刻恢复人类并移除感染节点 | B 当前仍依赖其传播链的后代进入断联窗口 | 人类迫使丧尸救援自己的网络 |
| `RELINK` 断联 D 接到稳定感染者 F | D 获得新父节点 | D 下属仍与其相连、未恢复的断联后代同步稳定 | 感染分支转移和保全 |

## 8.5 多树与跨树重连

如果存在 A、X 两名零号根，D 原来属于 A 树，在 A 树中断联后可以接到 X 树的任意**当前稳定且不是自身后代**的感染者。`rootId` 随之改成 X，D 下游未恢复节点一起迁移。

这使得 24 人局即使出现多个感染源，也不需要人为引入“丧尸红队/蓝队”。感染者依然是同一**胜利阵营**，区别仅在感染传播谱系。

以零号（含另一棵树的零号）为重连目标时，读条按 `RootRelinkHoldMultiplier` 延长（D2），以减缓“全员挂到零号”导致的树扁平化。`VirtualRoot` 不是实体，不能作为重连目标。

## 8.6 一次断链不人为封顶受影响人数

首版**不设置“最多只能断 5 人”这种违反树语义的硬限制**。例如 24 人局中，某枢纽下游有 12 人，成功治愈它就确实可能令 12 人进入断联，但：

- 解药数量有限；注射要求近距离持续交互；枢纽可以逃跑，队友可以护卫。
- 断联不等于立刻转人类；每个分支都有重连反制。
- 大分支意味着高价值目标，也意味着更应谨慎分散分支。
- VFX 根据手机性能分级，不能真渲染 12 条穿墙长连线。

如果实测频繁出现“一针必胜”，优先调**扫描精度、注射风险、断联时间、重连机会**，最后才讨论是否需要单次效应上限。

## 8.7 树形状与零号平衡（V1.1 新增）

蒙特卡洛模拟（评估文档 §3.2；未含空间因素，只用于判断方向）显示：

- 4～7 人局几乎不会出现 branchImpact ≥ 4 的可治愈节点，断链是 8 人以上的特色（§5.1）。
- 如果零号恰好是全场技术最强的玩家，他会直接感染大部分人，树变成以零号为中心的星形；24 人局中出现枢纽的概率会从约 80% 降到 13～33%。
- 反过来，一旦存在枢纽，最优一针平均可切掉约 40～60% 的感染者，“一针定胜负”的风险同样存在。

对应措施：零号扑咬冷却与被重连读条倍率（§6.2 第 6 条）、零号选择不按技术（§6.1）、扫描分级相对化（§12.3），并通过 `tree_shape_snapshot` 埋点（§22.2）用真实数据验证。

# 9. 感染判定与追逐动作

## 9.1 人类与感染者的基础能力

| 操作 | 人类 | 稳定丧尸 | 断联丧尸 |
|---|---|---|---|
| 行走、跳跃、翻越 | 是 | 是，动作不同 | 是 |
| 冲刺/短距离加速 | 消耗耐力冲刺 | 短扑咬冲刺有冷却 | 可短冲刺逃命，**不能咬人** |
| 开门、推动可交互路障 | 是 | 可推开普通路障 | 部分限制 |
| 武器（§9A） | 短棍（自带）、手枪/电击枪（拾取） | 不能使用 | 不能使用 |
| 被武器打倒、打死 | 否（没有生命值） | 是，死后复活 | 是，死后复活，断联倒计时不暂停 |
| 扑咬感染 | 否 | 是 | **否** |
| 医疗注射 | 是（有解药时） | 否 | 否 |
| 重连 | 否 | 可作为稳定目标协助断联队友 | 可主动寻找并发起 |
| 撤离 | 是 | 否 | 否 |

## 9.2 扑咬：输入简单，反馈明确

- 输入：PC 鼠标左键 / 手机屏幕右下明显攻击键 / 手柄映射（若首发支持）。
- 有 **0.35 秒可读攻击前摇**，然后短扑咬判定窗口；被咬成功转入 `INCUBATING`。
- 参考攻击有效距离和碰撞范围必须通过真实手机操作测试，不能只按 PC 精确鼠标设计。
- 扑咬未命中进入简短后摇，不允许点击脚本每秒触发数十次。
- 扑咬不能无限连击；推荐基础冷却 **4 秒**（BASELINE）。
- 玩家需有可观察的反制动作，例如快速转向、利用障碍、有限击退。新手被咬不应完全不知道发生了什么。
- 已有 `CURE_IMMUNITY`、`INCUBATING`、`INFECTED`、`UNSTABLE`、`EXTRACTED` 状态的目标，均不能再次作为普通新感染目标。

## 9.3 耐力与追逐平衡

建议第一版只给人类一个简单耐力条：

- 冲刺最多连续 5 秒；停止后自动恢复。
- 人类普通跑速略低于稳定丧尸，但短时间冲刺略快，形成追逐中的路线选择。
- 丧尸擅长**短距离爆发**，不能全程无脑高速追赶。
- 不限制视角转动，不允许出售“增加速度”的收费道具。

**不要在本文件把 WalkSpeed、JumpPower 写死成未经验证的正式数值。** 这些需要根据模型、网络延迟和实际碰撞半径调节。将速度、扑咬距离、冷却统一放在 BalanceConfig，并使用三端实机对照录像。灰盒阶段的起步值见 §24.4。

## 9.4 人类击退

> **V1.1（D10）起由 §9A 取代**：击退和短僵直由短棍、手枪和电击枪提供，数值见 §9A.4。以下 V1.0 原文保留作历史参考。

P0 只需要一种**非致命、非永久控制**的防御工具（例如应急脉冲器）：

- 近距离生效，击退/短僵直约 **0.7 秒**（BASELINE）。
- 不可连续无限击退。首次体验可按地图拾取 1 次，或通过 20 秒冷却使用；二选一做 A/B，不要两种经济系统同时做。
- 目标是制造救援机会，不是让人类通过连续硬控永久锁死零号感染者。


## 9.5 扑咬判定与延迟补偿（V1.1 新增）

手机网络往返延迟常在 100～250 ms，追击者在自己屏幕上“咬到了”、服务端却判定没咬到，是这类游戏最常见的差评来源。判定规则如下，所有数值进入 BalanceConfig：

| 项 | 规范（起点值） |
|---|---|
| 位置历史 | 服务端为每个参与者的 HumanoidRootPart 维护 **1 秒环形缓冲**，按 20 Hz 采样 |
| 回溯时间 | `rewind = clamp(attacker:GetNetworkPing(), 0, 0.25)` 秒（`GetNetworkPing` 的确切语义以官方文档为准）；取目标在 `now - rewind` 时刻的插值位置 |
| 判定 | 回溯位置与攻击者当前位置的距离 ≤ `BiteRange + BiteTolerance`；目标位于攻击者朝向 ±70° 锥内；两者之间没有静态遮挡（射线只检测地图静态碰撞组） |
| 起点数值 | `BiteRange = 5.5 studs`（两个根部中心的距离），`BiteTolerance = 1.5 studs` |
| 时序 | 客户端在前摇结束时发出 `TryBite`；服务端校验 `now - lastBiteAt ≥ cooldown` 和前摇窗口；同一次前摇只接受一个请求 |
| 手机辅助 | 客户端自动选取锥内最近的合法目标作为 `targetId` 提示，服务端仍独立复核 |
| 争议记录 | 判定失败但距离在 `BiteRange + 2 × BiteTolerance` 以内时，记录 `bite_near_miss` 埋点（§22.2），用于调参 |
| 与 Server Authority 的关系 | Roblox Server Authority（2026 年 7 月正式发布）负责移动合法性（防加速、穿墙）；扑咬命中仍按本节执行，因为官方的服务端回溯命中判定尚未提供。启用前在 Studio 中验证“阵营转换不重生、不重新挂载角色”的流程（论坛报告过角色重新挂载后客户端持续回滚的问题） |

## 9.6 输入与镜头（V1.1 新增）

- **PC**：默认第三人称，提供 Shift Lock；扑咬朝向取镜头方向。
- **手机**：右下角扑咬 / 交互大按钮；交互对象自动选取（最近、可见、合法）；读条期间按钮显示环形进度。
- **手柄**：P0 不宣传支持（§17.3）。
- 能力输入使用 `ContextActionService` 自定义绑定，**不使用 `Tool`**（`Tool` 装备状态对所有客户端可见，见 §17.6）。

# 9A. 轻射击对抗层（V1.1 新增，D10）

> 来源：产品负责人 2026-10-24 提出“第三人称射击 + 丧尸近战感染 + 感染链争夺 + 多人合作营救”，随后确认“丧尸可以被真正打死，死后以丧尸身份复活”。本章把它落成规则，**不改变感染树、断链、重连和胜负规则**。数值全部是 `BASELINE` / `EXPERIMENT` 起点，进入 BalanceConfig 后按实测调整。

## 9A.1 核心原则（LOCKED）

1. **击杀丧尸是暂时解除威胁，治愈丧尸才是改变阵营、切断感染链。** 只有解药能把非根感染者变回人类并切断感染链（§10、§11）。枪械、近战、电击、击杀都不会改变感染树。
2. **玩家丧尸可以被打死，但死亡不是淘汰。** 丧尸生命值归零后先倒地，倒地期间没被治愈就死亡，经过一段复活时间后在感染区以**原来的感染身份**复活（§9A.3）。玩家始终留在对局里。
3. **人类仍然没有生命值。** 对人类的唯一威胁仍是扑咬；人类之间没有友伤。
4. **武器制造战术机会，感染链决定胜负。** 武器稀缺、弹药有限，不做弹道、改装、配件和几十种枪械。
5. **分工各有位置。** 枪法好的负责压制和击杀；近战负责护送和打断；判断局势的负责挑选关键节点并注射。被感染的玩家切换为另一套操作，不失去参与权。

## 9A.2 不对称战斗能力

| 能力 | 人类 | 稳定丧尸（`INFECTED`） | 断联丧尸（`UNSTABLE`） |
|---|---|---|---|
| 远程 | 手枪（拾取）、电击枪（拾取，少量）；霰弹枪为 EXP | 无 | 无 |
| 近战 | 短棍（每人开局自带，见 §9A.4） | 扑咬（擒抱，§9A.6）；爪击为 FUTURE | 无攻击 |
| 控制 | 电击 1.5 秒；武器命中可打断扑咬前摇 | 擒抱 | 无 |
| 机动 | 耐力冲刺 | 更快的奔跑、短距离扑击 | 短冲刺逃命 |
| 生存 | 无生命值，被咬即尸变 | 生命值；归零倒地 → 死亡 → 复活 | 同左；断联倒计时不因死亡暂停 |
| 团队目标 | 火力击退 → 冒险救治关键节点 → 拦截重连 → 撤离 | 护链、打断注射、包抄射手、协助重连 | 重连 |

## 9A.3 丧尸的战斗生命周期：生命值 → 倒地 → 死亡 → 复活

丧尸的**战斗生命状态**与服务端保存的**感染身份**（主状态、感染树节点、`isRoot`、断联截止时间）分开存储。战斗生命状态的任何变化都不改写感染身份。

```mermaid
stateDiagram-v2
    [*] --> ACTIVE
    ACTIVE --> DOWNED: 生命值归零
    DOWNED --> CURED: 倒地期间完成注射（非根）
    DOWNED --> DEAD: 倒地时间结束
    DEAD --> ACTIVE: 复活时间结束，在感染区复活
    CURED --> [*]: 主状态变为 HUMAN，触发 §11 断链
```

| 规则 | 起点值 |
|---|---|
| 生命值 | 100（`ZombieMaxHealth`）；零号 ×1.25（`RootHealthMultiplier`，手枪多一发，延续 D2 的零号保护） |
| 伤害 | 手枪 25 / 发；短棍 20 / 次；霰弹枪见 §9A.4；电击不造成伤害，施加 1.5 秒电击控制 |
| 回复 | 4 秒未受伤后，每秒回复 25 |
| 倒地 | 生命值归零 → 倒地 **4 秒**（`DownedSeconds`）；不能攻击、不能交互，只能以 4 studs/s 爬行；不受武器伤害 |
| 死亡 | 倒地结束仍未被治愈 → 死亡：身体短暂僵直，化为红色感染粒子消散（不表现血液、肢解），角色离开战场 |
| 复活时间 | 按人数档：4～7 人 6 秒；8～15 人 8 秒；16～24 人 10 秒（`PlayerCountTiers[].zombieRespawnSeconds`） |
| 最后一只丧尸 | 如果场上已没有任何可行动的丧尸（全部倒地、死亡或尸变中），剩余复活时间缩短到最多 3 秒（`LastZombieRespawnCapSeconds`），避免小局长时间没有压力 |
| 复活地点 | 地图上的感染区（每张图至少 2 处）中选一处：距最近人类 ≥ 60 studs、距撤离区 ≥ 80 studs，优先选离人类最远的；撤离期不在撤离区附近复活 |
| 复活保护 | 复活后 2 秒不受伤害，主动攻击时立即结束 |
| 控制保护 | 电击结束后 5 秒内不能再被电击（`ControlImmunitySeconds`）；倒地中不能被电击 |
| 尸变中 | 不受武器影响（无法攻击，也不需要被压制） |

**感染树与死亡**（实现必须满足）：

| 情况 | 结果 |
|---|---|
| 关键节点 B 被打死 | 感染树不变：D、E、F 继续是 B 的下游，保持感染；B 复活后继续作为节点 |
| 关键节点 B 倒地时被治愈 | B 恢复 `HUMAN`，D、E、F 进入 8 秒断联（§11） |
| 死亡中的丧尸 | 仍是下游的合法上游，下游不断联；但它不在战场，不能作为重连目标，也不能被注射 |
| 零号被打死 | 复活，仍是根，仍不能被普通解药治愈 |
| 断联丧尸被打死 | 断联倒计时**照常继续**，死亡期间不能重连；倒计时在死亡期间到期 → 恢复 `HUMAN`（获得治愈保护），立即在人类安全出生点复活；不能靠死亡重新获得 8 秒 |
| 死亡中的丧尸，其上游被治愈 | 它按 §11 变为 `UNSTABLE`，倒计时在死亡期间照常走 |

**倒地是双方的争夺点**：治愈读条 2 秒（§10.2），倒地 4 秒、电击 1.5 秒都会让目标无法逃离，所以“击倒或电击 → 注射”是救治关键节点的标准打法。人类可以选择离开争取撤离时间，也可以冒险上前注射；越想彻底改变战局，越要承担风险。人类**不能补刀**提前结束倒地，保证治愈窗口完整。

**防止用死亡逃避解药**（服务端统一处理，§19.5）：

- 重置角色按钮禁用；Roblox 引擎死亡（`Humanoid` 死亡状态）不使用，生命值是服务端自己的数值。
- 丧尸在**倒地或被注射中**发生掉出地图、卡死、异常死亡：服务端把它放回最后的合法地面位置，倒地剩余时间继续，进行中的注射在施放者仍在范围内时继续。
- 丧尸在**可行动时**掉出地图或异常死亡：按正常死亡处理，走完整复活时间，不能借此快速换位。

**NPC 丧尸**（仅 EXP-06 等使用 NPC 的模式）：可以被打死，死亡后永久消失，不复活，也不是感染树节点。

## 9A.4 武器（P0 只做三种）

| 武器 | 级别 | 获取 | 关键数值（起点） | 作用 |
|---|---|---|---|---|
| **短棍** | `BASELINE` | 每名人类开局自带，不占武器位 | 范围 6 studs、前方 ±60°；间隔 0.9 秒；伤害 20；击退 6 studs | 人人都有的近身反制；命中可打断扑咬前摇 |
| **手枪** | `BASELINE` | 地图补给点拾取，每人最多 1 把枪 | 命中扫描；射程 80 studs；射击间隔 0.35 秒；弹匣 6、备弹 6；换弹 1.5 秒；伤害 25（满血丧尸 4 发倒地） | 中距离打断追击、击倒丧尸、为队友争取时间 |
| **电击枪** | `BASELINE` | 少量补给点拾取 | 射程 12 studs；2 发；冷却 8 秒；电击 1.5 秒 | 控制关键感染者，为注射创造窗口 |
| 霰弹枪 | `EXPERIMENT`（EXP-07） | 补给点 | 8 studs 内伤害 60，20 studs 衰减到 0；击退 10 studs；4 发 | 近距离救场；视 A0.5 测试结果决定是否进入 P0 |
| 消防斧等 | `FUTURE` | — | 只作短棍的外观变体，数值完全相同 | 不允许付费武器或付费数值差异（§18） |

**近战打断**：扑咬前摇（0.35 秒）期间，丧尸被短棍、手枪命中或被电击，前摇取消并进入正常扑咬冷却。这是人类的主要操作反制，也是近战的价值所在。

**射击噪声**：每次开枪，所有感染者在 HUD 边缘收到一个持续 2.5 秒的大致方向提示（`GunshotPingSeconds`），射手会暴露大致位置。开枪声本身对所有人公开。

## 9A.5 武器稀缺与补给

| N | 开局可拾取枪械（手枪） | 电击枪 | 解药（§10.1） | 弹药补给箱 |
|---:|---:|---:|---:|---:|
| 4～7 | 1 | 1 | 1 | 1 |
| 8～15 | 2～3（起点 3） | 1 | 2 | 2 |
| 16～24 | 4～6（起点 5） | 2 | 3 | 3 |

- 不含开局自带的短棍。补给点位置固定在地图上，内容在开局时按人数档生成。
- 弹药补给箱：每箱补满一把手枪的备弹，取用后 90 秒在同一位置刷新。
- 持枪者被咬后，枪与解药一样在尸变过渡结束时掉落（§10.1），可被其他人类拾取。
- **防火力碾压的检查项**（A0.5 必测）：开局 60 秒内零号是否能完成第一次感染；人类胜率是否落在 35%～65%；丧尸平均每分钟倒地/死亡次数；丧尸处于可行动状态的时间占比（目标 ≥ 70%）。
- **两端风险**：4 人小局里唯一的丧尸死亡时人类可能长时间没有压力（用“最后一只丧尸”复活上限缓解）；24 人大局里丧尸不断复活可能无限消耗人类（用弹药上限、按人数加长的复活时间和远离战场的复活点缓解）。枪械数量、复活时间和丧尸机动性按人数档一起调。

## 9A.6 扑咬改为擒抱感染（EXP-08，A0.5 做 A/B）

| 方案 | 机制 | 特点 |
|---|---|---|
| A：立即感染（对照组） | 扑咬判定命中即进入 `INCUBATING`（现行 §9.2） | 节奏快 |
| **B：擒抱感染（推荐）** | 扑咬判定命中后进入 **1.0 秒擒抱**（`GrabSeconds`），结束时才进入 `INCUBATING` | 队友有 1 秒开枪救人，合作感强 |

方案 B 的规则：

- 擒抱期间丧尸和人类都不能移动；人类不能使用武器，P0 不做连点挣脱（手机上不公平）。
- 擒抱期间丧尸受到任何武器命中、击退或电击，擒抱立即解除；人类获得 1.5 秒防扑咬保护（`GrabEscapeImmunitySeconds`），丧尸进入扑咬冷却。
- 擒抱判定继续使用 §9.5 的回溯命中；擒抱解除由服务端判定，以服务端收到的命中为准。
- 擒抱双方的状态是公开的（动作对所有人可见）。
- A/B 的观察指标：`grab_broken` 比例、被咬者主观“能不能反抗”评价、首次感染时间。

## 9A.7 命中判定（服务端权威）

- 枪械全部是**命中扫描**，不做弹道、下坠和穿透。
- 客户端发送 `Fire { weapon, origin, direction, targetHint? }` 等意图；服务端校验：开火间隔、弹药、`origin` 距本人头部 ≤ 4 studs、射程、目标回溯位置（复用 §9.5 的位置历史与 0.25 秒回溯上限）、对 `MapStatic` 的射线遮挡、目标阵营合法。
- 手机：触屏射击使用 6° 辅助瞄准锥（`TouchAimAssistDegrees`），服务端用同样的锥角复核，不额外放宽。
- 近战与电击同样走服务端距离、锥角和遮挡判定。
- 武器模型挂在角色上属于公开信息；能力输入仍用 `ContextActionService`，不用 `Tool`（§9.6、§17.6）。

## 9A.8 内容分级

- 表现采用风格化、非写实、非血腥：命中只用火花、电弧、踉跄和跪倒，倒地不表现血液、伤口或尸体。
- 加入枪械后需**按实际内容**重新填写 Content Maturity & Compliance 问卷（§27），结果可能影响可触达的年龄段（§2），发布前必须确认。

## 9A.9 本章新增配置键（Gate A0.5 时加入 BalanceConfig）

`WeaponsEnabled`、`ZombieMaxHealth`、`ZombieRegenDelaySeconds`、`ZombieRegenPerSecond`、`RootHealthMultiplier`、`DownedSeconds`、`DownedMoveSpeed`、`LastZombieRespawnCapSeconds`、`RespawnMinDistanceFromHuman`、`RespawnMinDistanceFromExtraction`、`RespawnProtectionSeconds`、`ControlImmunitySeconds`、`Weapons.Melee.*`、`Weapons.Pistol.*`、`Weapons.Taser.*`、`Weapons.Shotgun.*`（EXP-07）、`BiteMode = "INSTANT" | "GRAB"`、`GrabSeconds`、`GrabEscapeImmunitySeconds`、`GunshotPingSeconds`、`TouchAimAssistDegrees`，以及 `PlayerCountTiers[].pistols`、`.tasers`、`.ammoCrates`、`.zombieRespawnSeconds`。键名以 `BalanceConfig.luau` 为唯一来源，本节是加入前的清单。

# 10. 医疗救治：为什么要救“关键节点”

## 10.1 解药获得与供应

解药是阵营共有的稀缺战术资源：

| N | 本局解药总量（初始实验） | 获取方式 |
|---:|---:|---|
| 4～7 | 1 | 医院固定补给点 |
| 8～15 | 2 | 医院补给点 + 次级补给箱 |
| 16～24 | 3 | 医院补给点 + 两处战术补给点 |

- 解药不是每个玩家都自带；一名人类拾取后在本人道具位持有。
- 同一玩家最多持有 1 支，避免个人囤积全部资源。
- 持有者被咬后，在其**尸变过渡结束、公开成为 `INFECTED` 时**，解药掉在安全合法位置，允许其他人类拾取；过渡期间若因上游被治愈而恢复人类，则继续持有。掉落保持本局库存唯一，不复制道具。
- 解药耗费时机：**服务端确认成功治愈后消耗**；目标无效/中途取消不扣除，但有短冷却防止刷交互。
- 不能付费购买额外解药或仅为付费玩家提供治疗权限。

## 10.2 治愈动作与判定

1. 人类拿着解药接近一名**公开的稳定非根感染者**。
2. 玩家按住交互 **2.0 秒**，服务端持续验证距离、视线、持有道具、目标稳定状态及施放者人类身份。
3. 注射可被目标移动逃离、丧尸打断、施放者移动过远或玩家退出而中断。目标处于倒地或电击中时同样可以注射，这是标准打法（§9A.3）；目标电击结束后移出范围，读条中断；倒地结束时读条未完成则目标死亡，读条中断且不消耗解药。死亡中的丧尸不能被注射。
4. 成功时目标直接恢复 `HUMAN`，清理其感染节点和相关权利；受其感染而仍依赖该链的节点按第 11 章处理。
5. 治愈者与被治愈者都收到明确反馈；奖励结算避免重复领取。

**零号提示**：瞄准零号感染者时显示 `零号源头：普通解药无效`；不能让新手消耗唯一解药后才知道。

## 10.3 治愈后的保护

- 恢复人类后（含断联到期，或上游被治愈而取消尸变过渡）默认 7 秒短免疫（服务器数据），仅阻止再次感染，不阻止正常移动和撤离。
- 保护期有明确 HUD，但不会给角色隐身或免疫一切攻击。
- 如果保护期内再次收到扑咬输入，服务器拒绝感染并反馈“目标受保护”，不占用本局解药。
- 连续被治愈不能无限刷新额外奖励或累计永久免疫。

## 10.4 为什么不把“治疗”设计成简单扔飞针管？

短局多人混战中，远程无风险治疗可能让高价值枢纽的生存压力过大、从而摧毁丧尸阵营的乐趣。**首版用近距离读条制造风险与团队配合**。如果测试发现治疗成功率过低，可实验短距离投射式治疗，但必须同步调整准星、弹药和丧尸反制能力。

# 11. 核心机制：断链与 8 秒重连

## 11.1 从一棵树上切断节点

假设 `A(ROOT) -> B -> {D,E}`：

- 人类成功治疗 B：B 立即变回 `HUMAN`。
- D、E 以及其仍有效的下游公开感染者变成 `UNSTABLE`；每名受影响玩家得到**相同的 8 秒截止时间**（根据该次事件的服务端时间计算）。
- 提交时**立即解除 B 到直接子节点的全部有效边**，将这些子节点设为孤儿分支根（`parentEpisodeId=nil`），但保留分支内部的合法父子边；分支内相关公开感染者同时置为 `UNSTABLE`。服务端还可单独记录审计用的原关系快照，**旧父节点 B 不得残留为有效 parent**。
- 每一位本次断联的公开感染者记录同一服务器截止时间 `unstableEndsAt`，其内部旧链接仅用于支持“某个后代重连时带动自己的仍附属子树”；不会使已治愈者重新感染。
- 处于尸变过渡（`INCUBATING`）的下游是叶子：如其父链被治愈，则立即恢复 `HUMAN`、取消过渡计时并获得治愈保护（V1.1 起过渡是公开状态，无需静默处理）。
- 全局只显示“某条感染链断裂”；受影响丧尸获得更明确的倒计时和附近重连目标提示。

## 11.2 断联玩家能做什么？

**断联不是罚站动画**。断联的丧尸必须可移动、能看懂重连方向、能主动决定救自己还是帮助朋友。

- 可通过短冲刺靠近一名 `INFECTED`、且当前稳定的感染者。
- 按住重连交互约 1 秒（目标为零号时 × `RootRelinkHoldMultiplier`，即 1.5 秒），在合法半径内持续满足条件才完成；读条由服务端累计计时。
- 成功后该玩家及其**仍挂在它下属、尚未恢复**的断联分支整体稳定。若重连者原本是其他断联者的后代，先从旧断联父节点原子断开，再接到新稳定父节点，避免双父。
- 断联时不能再扑咬人类，不能占领人类撤离点，也不能当作新的有效传播源。
- 断联计时归零后，如果仍不稳定则变回人类，获得治愈保护。

## 11.3 复杂重连的简化例子

```text
最初： A(ROOT) -> B -> D -> H
                   └-> E

B 被治愈：D、H、E 全部断联（8秒）

情况 1：D 最先接到稳定 C
  D 和仍属于 D 分支的 H 立即一起稳定；E 继续倒计时。

情况 2：H 最先接到稳定 C
  H 从原断联分支脱离并恢复稳定；D 继续倒计时；E 继续倒计时。

情况 3：D、E、H 都没找到稳定目标
  全部在各自 8秒时限结束后恢复人类。
```

**禁止**因为重连把后代重新接到它自己身上造成环，或者让已治愈玩家“幽灵恢复感染”。

## 11.4 并发裁决规则

- 一个感染者同时收到 `BITE`、`CURE`、`RELINK` 请求时，**由服务器按接收顺序与状态版本执行**；每次状态变更后重新验证后续命令。
- 每项操作必须包含当前 `roundId` 和由服务端下发的合法目标引用；旧局消息、过期感染 episode、重复命令全部拒绝。
- 同一感染目标被两个人注射时，**只有先成功提交者扣除解药和获得救治奖励**；后一个动作被告知目标状态已变化。
- 断联剩余 0 秒与重连成功发生在同一服务器 tick 时，**以已获得服务器提交序号的操作先后为准**，客户端倒计时不参与判定。
- 局内一个断链事件广播只携带必要公开结果；详细的感染关系不发给无权限客户端。

## 11.5 8 秒断联窗口的平衡风险

| 观察结果 | 可能原因 | 优先调整 |
|---|---|---|
| 大多数断链毫无效果 | 附近稳定丧尸太密集，1 秒接触过于简单 | 重连距离、读条、可用目标提示范围 |
| 断链几乎必定清场 | 稳定丧尸太少、断联者移动能力不足 | 断联 8→10 秒实验、轻微加速、地图掩体 |
| 断联者不懂怎么重连 | 提示不清晰或目标不可识别 | 改 HUD、光圈和按键引导，先别增加规则 |
| 高频阵营来回跳 | 解药/再感染过密、保护期不足 | 增加恢复保护或限制总解药 |
| 关键枢纽永远藏着不出门 | 玩家获得过大被动优势 | 地图目标、可选扫描和枢纽活动激励 |

> 断链核心的“好玩”不来自永远让人类获利，而来自让丧尸必须在 8 秒内主动组织救援。

# 12. 感染扫描与情报博弈

## 12.1 为什么需要扫描？

玩家不应像开发者一样知道每棵树的所有结构。若信息完全隐藏，人类治愈就会变成碰运气；若所有关系持续公开，感染节点也没有隐藏与保护价值。

因此设计为：**人类必须付出时间和暴露位置的代价，换取近距离的有限感染情报。**

## 12.2 扫描装置

- 地图固定 1 个扫描控制台（大局可开放第二操作位置，但共享冷却）。
- 人类需持续交互 2 秒启动扫描，控制台发出**公开可听见**的警报，暴露附近有人类活动。
- 接下来 10 秒内，靠近扫描区的人类可看见局部感染目标的“关联规模”标记。
- 扫描范围建议从半径 40～60 Roblox studs 开始测试；通过地形与实机调整。
- 冷却建议 45 秒；**同一局禁止多名玩家绕过冷却并行扫描**。

## 12.3 人类扫描看到什么

| 目标状态 | 信息 | 说明 |
|---|---|---|
| 稳定非根丧尸、branchImpact = 1 | `单点感染` / `SINGLE` | 可治愈，但基本没有连锁收益 |
| 稳定非根丧尸、2 ≤ branchImpact < `HubThreshold` | `小型枢纽` / `BRANCH` | 有一定连锁价值 |
| 稳定非根丧尸、branchImpact ≥ `HubThreshold` | `关键枢纽` / `HUB` | 极具价值，值得团队配合 |
| 零号根 | `源头·不可治愈` / `SOURCE` | 阻止玩家误用解药 |
| 尸变过渡者 | `尸变中` / `TURNING` | 公开状态；不可注射，不显示其上游 |
| 断联感染者 | `断联中` / `UNSTABLE` | 其金色状态已是公开信息，不展示秘密上下游 |

**HUB 阈值（D3）**：`HubThreshold = max(HubMinImpact, ceil(HubRelativeShare × 当前公开感染者数))`，起点为 `max(3, ceil(0.2 × 公开感染者数))`。这样 8～15 人档也能出现“关键枢纽”，24 人局中只有真正的大分支才标为 HUB。阈值在扫描启动时由服务端计算，并在本次 10 秒扫描期间锁定。

**遮挡判定在服务端完成**：服务端从扫描控制台或扫描者头部向候选目标做射线检测（或使用预烘焙的区域可见性表），**只下发通过检测的目标**及其粗分类。不得把半径内全部目标下发给客户端再由客户端隐藏，否则作弊客户端即可透视。UI 只显示合法目标的有限信息；完整感染树只在对局结束后公开给参与者。

## 12.4 丧尸拥有的局部情报

- 任何丧尸都知道自己处于哪条稳定/断联关系中；可以看到自身上游的关键状态及直接下游的危险告警。
- 断联玩家可以获得附近合法重连对象的简单方向提示；该提示**由服务端计算**（含可达性与隔离区判断）后只发给本人，不下发其他候选者的位置。
- 丧尸阵营获悉“有人启动扫描”的公开警报，但**不自动获得所有人类的精确位置**。
- 可选 EXPERIMENT：丧尸枢纽看到“自己有几个仍稳定的后代”，提升保护意识。

## 12.5 扫描为何不应该变成第二主玩法

这是辅助决策工具，不是强迫玩家不停看复杂图表。初次体验 4 人局时，就算一个人不懂 `branchImpact`，也应能通过“红色敌人—金色断联—绿色恢复”自然学会追逐和救援。

# 13. 人类任务、撤离与胜负条件

## 13.1 为什么需要任务？

如果人类获胜只需躲 8 分钟，那么最优策略会变成一直躲在死角。任务必须迫使人类离开安全位置、暴露路线，但不能让对局变成修 12 台发电机的重复劳动。

## 13.2 撤离任务：恢复电力 → 开地铁门

P0 只有一个目标链：

```text
在地图开放范围内寻找并启动 1/2/3 个电力节点
                  ↓
地铁撤离系统准备完毕
                  ↓
最后90秒的撤离窗口到来
                  ↓
地铁门开启 → 人类进入撤离区域并读条
                  ↓
满足当前局需要的人类撤离人数 → 人类胜利
```

- 每个电力节点的交互应不超过约 3 秒，完成后永久激活，不会被普通丧尸无限复位。
- 节点位置须足够不同，增加移动选择；小局只开放最中心的一个节点。
- 即使人类很早修好电力，**撤离仍在最后 90 秒开放**，以确保有充分的感染争夺时间。
- 若进入最后 90 秒时任务尚未完成，地铁门保持关闭；玩家仍可继续修复，之后立即开放剩余撤离时间。
- 丧尸不能完成修复，也不能触发人类撤离；首版只通过追逐和控制通道阻止人类。
- 每位人类进入撤离区域需约 **2 秒无感染打断**才算成功撤离，避免从门口高速蹭一下就判赢。

## 13.3 正式胜负条件

**人类胜利**（满足任一）：

1. 在本局规定时间内，累计成功撤离的**独立人类玩家人数**达到第 5 章的阈值；或
2. 所有有效玩家感染源、公开丧尸、尸变过渡及断联状态都完全消失，且服务器经过短暂稳定性复核后确认**感染已被遏制**。

> 注：零号不可治愈，所以条件 2 实际上只会在零号全部离线、且虚拟根下也已没有感染者时触发。它是**边界兜底条件**，不是人类可以追求的策略；新手引导中不宣传此条件。

**丧尸胜利**（满足任一）：

1. 地图上已不存在有机会恢复/逃生的 `HUMAN`、`INCUBATING` 或 `UNSTABLE` 玩家，且在场全部未撤离玩家已经稳定感染，累计撤离人数又未达到人类胜利阈值；或
2. 对局倒计时归零，而人类没有达到撤离阈值。

> **防提前判输**：当剩余人类为 0、但存在 `UNSTABLE` 或 `INCUBATING` 时，不应立刻宣布丧尸获胜。必须等待这些尚未结算的状态完成，避免“最后一名人类可能 2 秒后从断联恢复，却被提前判负”。

> **没有平局**：如果倒计时归零前未达成人类胜利，丧尸胜；服务器在同 tick 处理的交互依据已确定的原子事件提交序号裁决，不使用客户端时间戳“抢判定”。

## 13.4 游戏内公开人数信息

不显示 `人类剩余 7 / 丧尸剩余 17` 这类全局真值文本（V1.0 的理由是保护潜伏身份；V1.1 起保留该限制，以便 EXP-01b 保密版本可以随时开启）。

P0 HUD 建议只显示：

- `24 名玩家进入本局`（开局时公开固定值）。
- `已撤离 2/4`（公开且真实）。
- `已公开感染者 8`（仅统计已完成尸变的感染者；可不显示）。
- `剩余时间 01:32` 与 `电力节点 2/3`。

个人知道自己的隐藏感染状态是合法的；感染树拓扑等秘密信息绝不通过全局统计泄露。

## 13.5 撤离阈值合理性

4 人局只需撤离 1 人，24 人局需要撤离 4 人，这是对“人数越多越容易有一个人从旁边溜走”的初始修正，并非数学上最优方案。

**A/B 重点**：24 人局比较 `撤离 3 人`、`撤离 4 人`、`撤离 5 人` 对最终阶段体验和双方胜率的影响。

# 14. 第一张地图：灰港医疗片区

## 14.1 空间结构

视觉圣经确定的地图为：**医院—庭院—中央街口—控制室—停车楼—地铁站**。本文件规定玩法用途。

```text
                 ┌─── [医院 / 解药点] ─── [控制室 / 扫描]
                 │          │                  │
    [小型庭院] ───┼─── [中央街口 / 争夺核心] ─── [停车楼]
                 │          │                  │
                 └────── [地铁入口] ────────────┘
                            │
                       [撤离站台]
```

## 14.2 各区设计目的

| 区域 | 对人类的价值 | 对丧尸的价值 | 必须避免 |
|---|---|---|---|
| 医院 | 获取有限解药 | 埋伏治疗者、堵住补给路线 | 只有一个入口导致堵门无解 |
| 中央街口 | 横向转场、绕路 | 围猎、快速碰头 | 完全开阔、没有反制空间 |
| 控制室 | 扫描关键感染者 | 通过警报判断人类活跃区域 | 透墙显示所有敌人 |
| 停车楼 | 高低差与逃生环线 | 高处截击、预测目标路线 | 楼梯、电梯复杂到迷路 |
| 地铁入口 | 终局集合、临时阻挡 | 控制撤离路线 | 单一狭窄入口永久封锁 |
| 侧街与庭院 | 小队迂回、分路 | 绕后、牵制 | 小局把玩家分散到找不到人 |

## 14.3 三条关卡设计原则

1. **任何核心地标至少两条有效路径**：防止单名丧尸无限守门，也允许玩家绕后救治。
2. **高价值节点附近有明确视野风险**：扫描站、解药点不应完全安全；风险来自路线选择而不是随机强制刷怪。
3. **追逐距离短、拐角有意义**：玩家转角能改变视线，但丧尸也能通过经验预测路线，不出现无穷的迷宫。

## 14.4 局内互动设施 P0 清单

| 设施 ID | 功能 | 玩家操作 | 首版数量 |
|---|---|---|---|
| `POWER_RELAY_*` | 恢复地铁电力 | 人类近距离读条 | 1～3 个根据人数开放 |
| `MED_STATION_*` | 领取有限解药 | 人类领取，库存计数 | 1～3 个 |
| `SCANNER_*` | 暂时揭示感染枢纽级别 | 人类启动，有全局冷却 | 1 个主控制台 |
| `DOOR_*` | 改变临时通路 | 符合距离可开启/关闭 | 若干，仅用于跑动与追逐 |
| `EXIT_ZONE` | 最终撤离 | 人类站入并短暂读条 | 1 个（至少两路可达） |

P0 不做复杂自动炮塔、车辆驾驶、大面积可破坏墙体、持续燃烧系统。它们会占用大量 QA 和网络同步预算，并分散感染树特色。

# 15. 一局中的社交博弈与涌现故事

## 15.1 应当自然出现的 8 种故事

1. **救错人**：人类把有限解药用在单点感染者上，却没能救到一名大枢纽。
2. **护链**：两名丧尸故意在关键枢纽附近保护其撤离危险区域。
3. **反向追逐**：关键枢纽被治愈后，原本追人的丧尸全体进入断联，开始逃离治疗者。
4. **异树迁移**：一条感染链被切断，断联玩家跨越地图向第二位零号感染者重连。
5. **朋友倒戈**：刚才被感染的队友，在后续断链中重新恢复人类，帮助抢撤离点。
6. **牺牲治疗**：人类为了救高价值枢纽冒险读条，自己随后被扑咬转化。
7. **终点堵截**：感染方不是随机追逐，而是判断人类修好了哪一条撤离路线。
8. **最后两秒重连**：断联玩家倒计时即将归零，冲进稳定丧尸身边完成 1 秒重连，成功保存分支。

这些故事必须主要由**基础规则自然生成**，不能每一种都靠预制动画或剧情触发器。

## 15.2 社交保护和反骚扰

- 不能对自己的现实朋友实施永久惩罚；所有感染仅在当前回合内有效。
- 禁止针对新玩家的长时间锁控、恶意无限复活击杀、断链后立刻重复感染等循环。
- 无需打开语音即可看懂队友的求救、重点感染节点、重连方向。
- 允许非骚扰性的表情与快捷语，正式文字聊天与用户互动遵守 Roblox 平台的内容和年龄相关规则。
- 持有解药或成为关键感染者时，不应因为公开标记被跨全图锁定追杀；情报有距离、时长和可见性约束。

## 15.3 对不同技术水平玩家的设计

- 新手可以做有价值的动作：从感染者身边逃开、修电力、守住解药、带人去地铁。
- 熟手有额外策略：利用扫描寻找枢纽、围绕断联重连建立战术、预判多条感染树路线。
- 技术差异应该提高操作或决策水平，而不是由永久装备属性造成数值碾压。

# 16. 新手引导：前 90 秒必须看见特色

## 16.1 第一次进入（不要求读长教程）

| 时间 | 玩家看到 | 玩家学到 |
|---|---|---|
| 0～10 秒 | 进入站前安全大厅，屏幕只有一个主目标 | 这是末日多人对抗游戏，不是装备商城 |
| 10～25 秒 | 练习一次冲刺或关闭一扇门，准备入局 | 最基本的移动与交互 |
| 25～50 秒 | “隔离突破”事件，某玩家公开开始尸变 | 原本是人类的队友会变成敌人 |
| 50～75 秒 | 有人类逃跑、有人感染另一玩家 | 感染可以层层传播 |
| 75～90 秒 | 小概率出现人类治疗或局部断链演示；否则给出一个短提示 | 救治关键节点可能使一群丧尸断联 |

以上是目标体验时序，不强制在无真实玩家事件时播放假的“多人断链”。如果真人对局没有发生该事件，新手可在**独立训练区**用两个演示 NPC 看一次不可计分的断链示例。

## 16.2 三个按钮先教会

- 人类：`冲刺`、`交互`、`击退/道具`。
- 丧尸：`扑咬`、`移动/跳跃`、`重连`（仅断联时出现）。
- 扫描、感染树、枢纽等级、撤离人数等为进阶提示，不在开局连续弹多张教学卡。

## 16.3 常见新手误解与即时反馈

| 误解 | 游戏必须怎么解释 |
|---|---|
| “为什么我突然成丧尸？” | 本人弹出 `你已感染：目标改为感染幸存者` |
| “为什么这支解药救不了？” | 瞄准根节点就提前告知 `源头不可治愈` |
| “为什么我变金色了？” | `你的感染链断开！8 秒内靠近稳定感染者重连` |
| “我一直躲着，怎么还是输了？” | 对局目标显示 `先恢复电力，再赶往地铁撤离` |
| “为什么我成功跑到出口却没赢？” | 明示 `成功撤离 1/4，仍需更多人逃出` |

## 16.4 留存风险

Roblox 官方的 FTUE 指引强调尽快让用户进入乐趣和理解核心循环。我们应统计完整的新手漏斗，而不是仅看游戏 DAU。官方入口：<https://create.roblox.com/docs/production/game-design/onboarding>。

# 17. UI、HUD、角色信息权限与无障碍

## 17.1 对局 HUD 必须包含什么

| 信息 | 展示对象 | 优先级 | 说明 |
|---|---|---|---|
| 我是谁 / 我现在的阵营 | 本人 | P0 | 尸变过渡者看到倒计时；状态文案按 §7.5 映射 |
| 剩余时间 / 当前目标 | 所有活跃玩家 | P0 | 任务不同阵营分别描述 |
| 断联剩余秒数 | 断联本人 | P0 | 服务端截止时间，客户端只做平滑显示 |
| 医疗注射进度 | 正在使用解药的人类 | P0 | 可清楚看到取消原因 |
| 扑咬冷却 | 稳定感染者 | P0 | 对应操作反馈 |
| 已撤离数量 / 目标 | 所有人 | P1 | 不包含秘密信息 |
| 人类扫描标记 | 有权限且在范围内的人类 | P1 | 临时、局部、非精确树图 |
| 感染来源和完整传播树 | 结算时相关对局参与者 | P2 | **结算后**公开，无局中泄密 |

## 17.2 信息权限矩阵

| 资料 | 人类客户端 | 丧尸客户端 | 尸变过渡者本人 | 在场外等待者 |
|---|---|---|---|---|
| 已公开的人物外形和动画 | 可见时 | 可见时 | 可见时 | 不可获得局内秘密 |
| 某玩家处于尸变过渡 | 公开（V1.1） | 公开 | 可见自己与倒计时 | 不可获得局内秘密 |
| 全部感染树拓扑 | 禁止 | 禁止作为默认全量广播 | 禁止 | 禁止 |
| 自己的直接感染关系 | 自己是人类则无 | 可看自身局部 | 仅私有有限提示 | 无权限 |
| 扫描揭示的枢纽级别 | 符合范围/时限可见 | 只有公开扫描事件 | 不额外获得 | 无权限 |
| 本局最终传播树 | 结算后可见 | 结算后可见 | 结算后可见 | 不可提前看 |

**实施约束**：不能把私有感染数据塞到 `ReplicatedStorage`、Workspace Attributes 或默认 `Teams` 公共展示中，再寄希望于 LocalScript 把它隐藏。只发送客户端有权知道的数据。

## 17.3 三端交互

- **PC**：鼠标键盘；移动与镜头直接响应，医疗注射与按钮位置明确。
- **手机**：横屏、拇指舒适区、右下扑咬/道具大按钮、附近目标自动辅助选取；**不能要求拖动复杂感染树**。
- **平板**：采用与手机相似的自适应布局，避免 UI 缩得过小。
- **手柄**：允许后续加入，但如果未完成手柄操作和 QA，不应在发布说明中称为“全面支持”。

## 17.4 可访问性

- 状态用**颜色 + 轮廓 + 图标 + 动画/文字**同时表示；遵守视觉圣经设计 Tokens。
- 提供“低闪烁”“降低屏幕震动”“简化粒子”三个开关。
- 关键音效需有对应的字幕或短文字反馈；不强制使用语音聊天。
- 角色与地图不因手机低画质变得完全看不清。

## 17.5 本地化与首发语言（V1.1 新增，D9）

- 首发主语言为**英文**：商店页标题与描述、缩略图文案、局内 UI 默认英文。
- 所有 UI 文案进入 LocalizationTable，开启 Roblox 自动翻译；中文（简体/繁体）是本地化语言之一。
- 第二批人工校对语言建议：西班牙语、葡萄牙语（巴西）、印尼语、菲律宾语、泰语，以 Creator Analytics 的地区分布为准。
- 对外主标题为 `BREAK THE CHAIN`，上线前在 Roblox 内查重；`断链` 作为中文本地化名称。
- 文案不得烘焙在贴图中（与视觉圣经 §7.4 一致）。


## 17.6 Roblox 引擎层泄密面清单（V1.1 新增，QA 必查）

秘密信息（感染树拓扑、扫描结果、重连目标，以及 EXP-01b 开启时的潜伏身份）**只要改变了下列任何一项，就等于向所有客户端广播了它**：

| 引擎面 | 风险 | 规定 |
|---|---|---|
| `Player.Team` / `TeamColor` | 默认玩家列表和名牌颜色会显示 | 不用 Teams 表示阵营；如果要用，只在**公开转换**时修改 |
| `Instance:SetAttribute`（Player、Character 上） | 属性复制给所有客户端 | 角色上只放公开状态；秘密数据只存在服务端内存中 |
| `Humanoid.WalkSpeed`、`JumpPower`、`DisplayName`、`HealthDisplayType` | Humanoid 属性会复制 | 秘密状态期间不修改；速度差异只在公开转换后生效 |
| `Tool` / Backpack | 装备中的 Tool 对所有人可见 | 能力输入用 `ContextActionService`，不用 Tool（§9.6） |
| `leaderstats` | 默认排行榜公开 | 只放公开统计 |
| 动画轨道和音效 | 在角色上播放会被复制 | 秘密阶段不播放阵营专属动画和音效 |
| `CollisionGroup`、零件属性 | 复制 | 只在公开状态下切换 |
| `ReplicatedStorage` 中的任何对象 | 所有客户端可读 | 不放局内秘密数据 |
| 挂在角色上的 `Highlight`、`BillboardGui` | 服务端创建的会复制给所有人 | 私有标记**由客户端本地创建**，内容来自 `FireClient` 的定向数据 |
| `FireAllClients` | 广播 | 公开事件只携带公开字段；私有事件一律 `FireClient` |

**QA 方法**：测试版本提供开发者面板，以“人类客户端”视角列出该客户端能读到的所有 Attributes、Team 和收到的 Remote 载荷，与 §17.2 权限矩阵逐项比对。审计失败属于 release blocker（§23.5）。

# 18. 局外奖励、成长与商业化

## 18.1 核心原则

**游戏胜负由局内技术与策略决定，商业化不改变阵营战斗数值。** 首发先验证留存，等追逐与断链体验稳定后再上线商城。

## 18.2 初始结算分数

以下分数是“展示贡献”的非竞技币值，不作为强制结算奖励倍率依据。

| 事件 | 展示分数建议 | 反刷限制 |
|---|---:|---|
| 完成电力节点 | +30 | 一局同一节点只计一次 |
| 成功扑咬感染一名人类 | +40 | 每次有效感染 episode 仅记一次；同一对玩家频繁互转递减 |
| 成功治疗感染者 | +50 | 仅对实际状态提交成功者奖励 |
| 击倒丧尸（造成最后一击） | +10 | 同一目标 60 秒内只计一次；救治比击杀得分更高，引导玩家去断链而不是刷击杀（D10） |
| 击倒的丧尸随后被队友治愈 | +15（助攻） | 每次治愈只给一名助攻者 |
| 引发断链并使至少一人到期治愈 | +20/人（可封顶） | 按实际恢复人类人数记账，非按树预测 |
| 断联后成功重连 | +30 | 同一玩家单位时间内重复重连不累计无限收益 |
| 成功撤离 | +60 | 每个玩家每局仅记一次 |
| 本阵营胜利 | +80 | 需要满足实际参与时长/反 AFK 规则 |

## 18.3 不鼓励的不良行为

- 不奖励玩家故意连续给朋友感染→治疗→感染刷积分。
- 不奖励“在地图角落挂机直到胜利”。
- 不因被随机选为零号感染者就给予永久额外币值，避免刷选源头。
- 不允许付费玩家购买零号资格、解药数量、感染冷却优势或优先获胜。

## 18.4 外观商业化建议

| 类别 | 具体示例 | 是否影响判定 |
|---|---|---|
| 丧尸外观 | 侵蚀纹路、制服变异款式 | **否**，统一判定体积 |
| 角色服饰 | 末日风外套、护目镜、背包装饰 | 否 |
| 胜利/撤离动作 | 车厢庆祝、团队合照姿势 | 否 |
| 感染与治愈特效 | 彩色裂纹形状、有限装饰音 | 否，必须保留阵营语义和低端性能 |
| 称号和名牌 | “断链高手”“最后幸存者” | 否 |
| 自定义大厅空间 | 海报、玩具装饰 | 否，不改变对局通路 |

**付费边界**：不售卖尸变过渡时长、扑咬范围、治疗距离、耐力、私人扫描范围等属性；也不售卖可让敌方难以辨认的外观。

## 18.5 Roblox 变现接口

- 一次性外观权益可用 `Passes`，可重复购买的纯外观礼包可评估 `Developer Products`。
- 真实购买验证应使用 Roblox 官方购买流程和服务器侧结果校验，保证幂等、防止同一收据重复发放。
- **P0：不接真实内购**，保留 UI 插槽和数据结构；付费 SKU 与价格由后续 A/B 测试确定。
- 不用“随机付费箱”绕过适用于未成年人的政策和披露要求。

官方参考：<https://create.roblox.com/docs/production/monetization/passes>、<https://create.roblox.com/docs/production/monetization/developer-products>。

## 18.6 持续游玩的长期目标

先选择低成本、无数值膨胀的循环：

1. 每局获得一定的非战力经验，解锁外观色板、名牌。
2. 每周挑战（例如“救回 3 名队友”“完成 5 次重连”）由**不作弊的有效对局数据**驱动。
3. 结算展示个人感染传播分支与拯救人数，形成有分享价值的回忆。
4. 首次体验后可邀请朋友组队开局；后续优化社交邀请与队伍进入同一服务器的稳定性。

**不做**新玩家需要刷 100 局才能得到正常移动速度的设计。


## 18.7 Creator Rewards 与回访驱动（V1.1 新增）

- Roblox 自 2025 年 7 月起以 **Creator Rewards** 取代 Engagement-Based Payouts：活跃付费用户每天在某个体验中停留满 10 分钟，且该体验是其当天最先打开的三个之一时，创作者获得固定 Robux；单日超过 10 分钟不再增加收益。领取需要身份验证账号和有效的 DevEx 账号。
- 这意味着**“当天第一个打开”和“每天回来”比单次时长更重要**，直接支持本作“短局、连续重开、每日挑战”的方向。
- 因此每日挑战（§18.6 第 2 条）从 P2 提前到 **Gate D**：它是成本最低的回访驱动。挑战进度只认正式局（§5.2）。
- 其余条目维持本章的非 P2W 原则；具体规则以官方文档为准：<https://create.roblox.com/docs/creator-rewards>。

# 19. 退出、掉线、重入与恶意行为边界

## 19.1 退出节点规则（必须做对）

| 退出者状态 | 服务端行为 | 为什么这样设计 |
|---|---|---|
| 普通人类 | 视为未撤离玩家离场；不计逃生成功 | 避免退出等于逃出 |
| 尸变过渡中 | 删除其叶子与当前 episode，父节点不受影响 | 不留下幽灵感染者 |
| 稳定非根感染者、仍有后代 | 直接子节点挂接到该退出者的当前**稳定上游**；其下游保持稳定 | **退局不应触发免费断链** |
| 零号根、仍有后代 | 保留该树非实体 `VirtualRoot`，原直接子节点仍稳定 | 不把退出当作免费解药，也不强制提升另一玩家为不可治愈 |
| 断联感染者、仍有后代 | 删除离开节点，下游继承本次断联事件截止时间；若有上游断联节点则挂接其上 | 不让退出为下游重置 8 秒时限 |
| 已撤离玩家 | 本局撤离进度继续保留 | 不因网络掉线撤销合法撤离 |

所有离线删除都必须在服务器感染图的同一事务队列完成，绝不能直接删 Roblox Player 实例后留一条悬挂 parent 指针。

## 19.2 网络中断与重入

- Roblox 平台不保证掉线后一定能重回原服务器。因此首版 **不承诺断线重连恢复原局位置**。
- 若确实重进原 Place 的同一在进行中的服务器：按 §5.2 中途加入规则作为新参与者进入（新的 episode，不恢复旧身份与旧关系）。
- 若重进新服务器：正常等待下一局。
- 已完成的合法外观解锁 / 奖励通过 DataStore 持久保存；仍需防重放。
- 若未来需要“30 秒内回原局”，另行设计受控的重连令牌、占位状态、Teleport 与防刷机制，**列 FUTURE**。

## 19.3 僵局与 AFK

- 若全局感染事件未触发，按第 6 章保底或遏制胜利结束。
- 若没有真实人类可以继续完成任务，且没有断联恢复可能，允许服务端提前判丧尸胜利。
- 连续无输入/明显挂机者，可给予提示、降低战绩结算资格；**不能简单因为静止 10 秒就判定 AFK**，因为伏击和潜伏本来可能需要等待。
- 恶意反复退出/重入以操控胜负，记录异常行为并以平台规则允许的方式限流，禁止滥用处罚。

## 19.4 关系操作的高级边界

- **切 B 后再切 D？** D 已断联，不可再次治愈；若 D 已重连恢复稳定，则可以作为新的合法治疗目标。
- **断联期间被新扑咬？** 断联玩家已经是感染阵营，不是可感染人类；普通咬击无效。恢复人类后才可再次被感染。
- **尸变过渡者的父节点被救回？** 过渡者立即恢复人类并获得治愈保护；旧倒计时取消。
- **已撤离者原是感染树前成员？** 只有已恢复为人类并满足撤离条件才能成功撤离；从树中清理，不应影响其他已稳定感染者。
- **两个断联者想互相重连？** 不允许。目标必须是稳定感染者，避免形成永久不受任何根支撑的环。
- **两名玩家同时请求重连给彼此？** 若双方都不稳定，则都拒绝；如果一方已先稳定，后来的请求在新状态下重新验证。
- **根退出后可以治疗子树吗？** 可以，子树所有非根在场感染者仍可被人类治疗；`VirtualRoot` 本身无可互动对象。


## 19.5 回合循环必须处理的引擎事件（V1.1 新增）

| 事件 | 规定 |
|---|---|
| 玩家点击菜单中的“重置角色” | `StarterGui:SetCore("ResetButtonCallback", false)` 禁用；服务端仍需处理 Humanoid 死亡 |
| 掉出地图 / 卡死 / 意外死亡 | 在最近的安全点重新生成，**保持当前阵营与感染图状态不变**，并取消进行中的读条。例外（D10）：丧尸倒地或被注射中时放回最后的合法位置并继续倒地；丧尸可行动时按正常死亡处理并走完整复活时间（§9A.3） |
| `CharacterAutoLoads` | 由 RoundService 控制生成时机；阵营转换时**不重新生成**角色。唯一的重新生成是丧尸死亡后的复活（§9A.3），以及断联在死亡中到期后在人类出生点生成 |
| 回合重置时的资源泄露 | 每局创建的连接、计时器、实例统一用清理器（Trove / Janitor 一类模式）在回合结束时释放；测试 R-12“连续 50 局”加入**服务端内存曲线**检查 |
| StreamingEnabled | 远处角色可能没有流式加载到客户端。世界空间提示（重连方向、扫描标记）由服务端计算并下发坐标或方向；角色模型的流式模式设为 `Persistent` 或 `Atomic`，并评估内存影响 |
| 服务器关闭（版本更新） | 在 `game:BindToClose` 中尽力保存奖励数据，不尝试持久化对局状态 |

# 20. Roblox 技术实现边界——服务端权威

> 本章属于供技术设计和 Coding Agent 使用的**实现契约**，不是完整可直接运行的最终 Luau 源码。具体组件名称可以调整，但职责、权限和数据不变量不能删减。

## 20.1 原则：基础服务无需自建游戏服务器

Roblox 托管游戏对局；编写在 Roblox 服务端执行的 Luau 脚本。不用第一天购买 ECS、Kubernetes 或自建 WebSocket 服务器承载实时感染对抗。

官方关键能力：

- `Players`、`ServerScriptService`、`ReplicatedStorage` 与 `RemoteEvent` 用于玩家、服务端逻辑和交互事件。
- `DataStoreService` 保存跨局外观/奖励等低频持久数据。
- `MemoryStoreService` 适合以后跨服务器匹配队列，**首版不依赖**。
- `TeleportService` 用于以后大厅与比赛 Place 分离，**首版可不使用**。
- `CollectionService` 可标记可交互门、医疗站、扫描站、电力节点等。
- `RunService`/统一服务器时钟用于可信对局计时；客户端倒计时仅供展示。

> 官方服务器权限、安全与匹配入口：<https://create.roblox.com/docs/scripting/security/security-tactics>、<https://create.roblox.com/docs/matchmaking>、<https://create.roblox.com/docs/projects/server-authority>。

## 20.4 不可相信客户端发送的内容

**客户端只发送动作意图，不发送结果**。

正确示例：

```lua
-- 客户端：仅请求一次扑咬，命中交给服务端算。
RequestAction:FireServer({
    action = "TryBite",
    requestId = locallyUniqueId,
    targetId = possibleTargetParticipantId, -- 仅供服务器检验，不能当作命中事实
})
```

错误示例（禁止实现）：

```lua
RequestAction:FireServer({
    action = "SetPlayerInfected",
    targetUserId = 12345,
    infected = true,
    parentId = 67890,
    distance = 0,
})
```

任何 `state`、`parent`、`subtreeSize`、`cureSucceeded`、`winner` 都必须由服务端计算。攻击命中必须服务端验证几何、视线、冷却、状态、移动合理性和必要的延迟容忍（规范见 §9.5）。

## 20.5 服务器原子事件处理（逻辑伪代码）

```text
handleAction(player, command):
    assert player belongs to current round
    assert command.roundId == current roundId OR command arrived on round-scoped channel
    rateLimit(player, command.action)
    validateExpectedStateAndEpisode(player, command)
    validateServerObservedPositionAndAllowedDistance(player, command.target)
    validateLineOfSightAndCooldown(command)

    serializeOnRoundMutationQueue(function():
        read latest player/node version
        reject if version or state invalid
        apply one graph/state transition
        graph.assertInvariants()
        bump changed versions
        append immutable event with seq and server timestamp
        notify only authorized clients of relevant public/private deltas
        schedule victory re-evaluation
    end)
```

实现可以使用同步的统一服务器事件处理器或队列；原则是**单场感染图永远单写者、无交叉 yield 的修改事务**。外部 DataStore IO 不得卡在感染图的临界路径里。

| Public | `RoundResult` | 胜方和公开结算信息 |
| Public | `InfectionTurning` | 某人进入公开尸变过渡（不含其上游） |
| Private | `YouAreIncubating` | 本人已感染及尸变倒计时 |
| Private | `YouAreUnstable` | 本人断联计时、可重连对象指引 |
| Private | `ScannerResults` | 临时授权的目标级别数据 |
| Private | `CureChannelProgress` | 本人医疗读条与取消原因 |
| Private | `BranchWarning` | 合法下游或上游危险提示 |

**重连/治愈结算的私有事件不得从一个 `FireAllClients` 里夹带完整感染拓扑。**

## 20.8 局内实时数据 vs 持久数据

| 数据类型 | 放在哪里 | 备注 |
|---|---|---|
| 正在进行的感染树 | 当前 Roblox 服务器内存 | 每局重置、频繁变化、绝不需要每次写 DataStore |
| 断联计时、冷却、临时扫描 | 当前 Roblox 服务器内存 | 同一 roundId 绑定 |
| 局内电力开关、撤离人数 | 当前 Roblox 服务器内存 | 服务端广播公开部分 |
| 皮肤、称号、结算进度 | DataStoreService | 低频更新、失败重试、版本号/幂等 |
| 未来的跨服务器匹配队列 | MemoryStoreService（FUTURE） | 仅在默认匹配不满足需求时使用 |
| 统计和玩家反馈 | 受控埋点/日志 | 不采集多余个人身份或聊天内容 |

Roblox 官方说明 DataStore 用于持久进度，MemoryStore 适用于跨服务器临时数据：<https://create.roblox.com/docs/cloud-services/data-stores>、<https://create.roblox.com/docs/cloud-services/memory-stores>。

## 20.9 参与者抽象与 Bot（V1.1 新增，D4）

```lua
type ParticipantId = string -- "U:<userId>" 或 "B:<botIndex>:<roundId>"
type Participant = {
    id: ParticipantId,
    kind: "Player" | "Bot",
    player: Player?,   -- 仅真人
    character: Model?,
}
```

- `InfectionGraphService`、`PlayerStateService`、`RoundService` 及 `logic/` 下的纯逻辑**只认 ParticipantId**，不直接引用 `Player`。纯逻辑测试与 Bot 因此共用同一套代码路径。
- **Bot 行为（P0 够用即可）**：人类 Bot 前往最近的未完成电力节点，遇到威胁沿路点逃离，撤离期前往出口；丧尸 Bot 追击视野内最近的人类，断联时前往最近的稳定感染者重连。路径优先使用关卡中手工摆放的路点图，`PathfindingService` 作为兜底。
- Bot 的动作同样经过 `handleAction` 校验和单写者队列，不绕过任何规则。
- Bot 不产生任何持久化奖励、排行榜或挑战进度；真人在练习局中的行为也不计正式奖励（§5.2）。
- **测试用途**：开发配置可用 `DebugForceBotFill` 把参与者补到 24 人，用“Studio 8 个本地客户端 + 16 个 Bot”近似 24 人局，测量服务端事件处理与广播字节数；客户端渲染压力仍须真机验证（§21.5）。
- 服务器上 Bot 数量建议 ≤ 18，避免服务端寻路和物理开销失控。

# 21. 反作弊、安全与性能预算

## 21.1 防作弊威胁模型

Roblox 官方明确提醒：任何客户端发出的数据都可能被篡改，包括交互距离、位置、Touch 事件和 RemoteEvent 参数。**不能把 `Touched` 或客户端命中回调单独作为“被咬成功”的证据。** 参考：<https://create.roblox.com/docs/scripting/security/security-tactics>、<https://create.roblox.com/docs/physics/network-ownership>。

| 攻击方式 | 潜在结果 | 必须防护 |
|---|---|---|
| 伪造远距离扑咬 | 跨地图感染别人 | 服务端距离、视线、动画窗口、位移合理性验证 |
| 修改客户端状态 | 变成不可治愈丧尸/无限免疫 | 状态只在服务器产生，客户端只展示 |
| 伪造救治成功 | 无限解药、强制清除尸群 | 持有库存与目标校验、原子消费、幂等 |
| Spam RemoteEvent | 卡顿或状态机竞争 | 玩家/动作双层频率限制、大小限制、异常日志 |
| 伪造重连关系 | 构造环、无限延长倒计时 | 目标稳定合法、无环、保留原 deadline |
| 提前读取隐藏信息（感染树拓扑、扫描结果） | 破坏公平 | 数据权限最小化，不复制秘密到客户端 |
| 退出触发感染树错误 | 退局免费恢复队友 | 第 19 章退出补链与虚拟根规则 |
| 角色移动速度作弊 | 秒扑咬、越墙逃跑 | 服务端移动异常检测，谨慎考虑网络延迟 |
| 客户端物理对象篡改 | 远程碰撞假命中、抛飞 | 关键交互避免依赖不可信网络所有权 |
| 购买回执重放 | 重复获得付费道具 | Roblox 官方交易回调 + 服务器幂等记录 |

## 21.2 实现要求

- 对所有动作命令校验 `player` 当前局、角色状态、冷却、目标有效性、目标距离、当前地图区、是否被暂停。
- 每名玩家每秒允许的请求次数由功能决定；超过阈值先拒绝并埋点，不要误封弱网用户。
- 非法命令不应改变本局任何图结构、经济余额或胜负结果。
- 对明显不可能的位移记录证据；考虑网络抖动与 Roblox 角色物理网络所有权，不能仅凭一次瞬移就自动认定作弊。
- 将反作弊和权限规则作为 CI 测试的一部分，而不是上线前人工目测。
- **读条交互由服务端计时**：解药、重连、电力、撤离等读条如果用 `ProximityPrompt.HoldDuration` 实现，按住时长是客户端判断的，作弊工具可以直接触发完成事件。服务端在收到开始请求时记录开始时间和状态版本，每个 Heartbeat（或每 0.1 秒）重新校验距离、状态和视线，只有服务端累计时间 ≥ 所需秒数时才提交；`Triggered` 只当作意图，不当作完成的证据。
- 移动合法性优先评估 Roblox Server Authority；扑咬命中按 §9.5 自行判定。

## 21.3 24 人规模的性能目标（BASELINE）

| 指标 | 初始验收目标 | 实测方式 |
|---|---|---|
| 低端基线手机帧率 | 24 人可玩压力场景尽量维持 **≥30 FPS** | 选定实际旧款 Android 与 iPhone，记录平均、1% low 和卡顿 |
| 服务器状态机成本 | 重连/治疗时不出现可感知的长期脚本卡顿 | MicroProfiler / 性能统计 / 日志 |
| 24 人满局下断链 | 一次影响 10+ 节点时不重复广播整棵图 | 网络流量、CPU、效果档位观察 |
| 掉线与重入 | 不出现双方无法获胜或服务器崩溃 | 8 客户端本地模拟 + 真实 24 人场次 |
| 移动端交互 | 感染、治疗、重连均可完成 | 真机触控录像和任务成功率 |

Roblox 官方强调应选定低端基线设备持续测试，并合理使用 Streaming 等优化手段：<https://create.roblox.com/docs/performance-optimization/design>。

## 21.4 实施优化优先级

1. **少量可重复利用的实体 NPC**：初始感染源 NPC 不变成持续产生数百物理丧尸的系统。
2. **事件驱动感染图**：只在感染、治疗、重连、退出时变更；不每帧遍历全部祖先和子孙。
3. **按需扫描与局部网络快照**：不每帧全图复制感染树。
4. **计时归档**：使用最早到期事件队列或定时调度，不为每个感染节点独立开无限 while loop。
5. **动画与 VFX 分级**：靠近者完整效果，远处只显示公开要点，不用满屏连接粒子。
6. **地图与模型预算**：优先保证角色动作辨识、核心门洞和出口地标，遵守视觉圣经的资产规范。

## 21.5 关于 Studio 测试上限

Roblox Studio 的 **Server & Clients / StudioTestService 一般最多模拟 8 个客户端**。这只是 Studio 本地多客户端测试能力，不是线上正式服务器只能有 8 名玩家。**16 与 24 人验收必须组织真实账号/设备的测试场次或相应正式联机测试**，不能说“8 人过了就代表 24 人性能过了”。

官方文档：<https://create.roblox.com/docs/studio/testing-modes>。

V1.1 补充：可用 Bot 补位（§20.9）在本地近似 24 人局的**服务端**负载，但这不能替代真人真机的客户端性能验收。

# 22. 数据埋点、玩家反馈与验证指标

## 22.1 为什么测试比继续加机制更重要

游戏不是“功能越多越好”。需要尽早证明三件事：玩家愿意加入第二局；转成丧尸后不会离开；断链确实改变了决策，而不只是偶然播放大特效。

## 22.2 关键事件埋点

所有事件应有 `eventId`、`roundId`、`serverTimestamp`、`playerKey`（必要时脱敏）、`playerCountBracket`、`buildVersion` 等公共字段；不要采集聊天正文、精确现实定位或不必要的私人信息。

| `infection_revealed` | 尸变过渡结束 | `episodeId`, `timeIncubating` |

| `cure_committed` | 成功救回非根感染者 | `branchImpactBefore`, `unstableCount` |

| `relink_committed` | 重连成功 | `relinkedSubtreeCount`, `secondsLeft` |

| `scanner_used` | 扫描成功 | `visibleTargets`, `hubTierCounts` |

## 22.3 关键漏斗（Funnel）

```text
游戏入口曝光
  -> 点击进入
  -> 大厅加载完成
  -> 进入有效对局
  -> 看见第一次公开感染
  -> 自己第一次积极参与（扑咬/防御/修电力/救治）
  -> 完成一局
  -> 点击“再来一局”
  -> 下一次回访
```

## 22.4 初始内部 KPI——全部是实验目标，不是官方基准

| 维度 | 暂定内部目标 | 解释 |
|---|---|---|
| 快速开局 | 4 人达到开局条件后通常 30～45 秒内入局 | 排除极端客户端加载与失败 |
| 首次核心体验 | 新人前 90 秒内看见一次感染或断链引导 | 让规则变得具体 |
| 对局完成率 | **≥80%** 的参与者到本局正常结算 | 留意退出的真实原因 |
| 双方胜率 | 大多数人数档各约 **40%～60%** | 仅作调参起始区间，不追求所有档同分布 |
| 断链参与 | 至少 30% 的有效对局发生过治愈关键分支 | 太低说明核心特色少见 |
| 重连可感知性 | 断联玩家中多数能理解“要去找谁、如何操作” | 用首次行为与访谈联合判断 |
| 再来一局点击率 | 从 30% 的内部假设起步，持续优化 | 与实际总时长和好友行为合看 |
| 移动端操作成功率 | 玩家能够可靠完成扑咬、注射、重连 | 每种操作看取消原因与操作错误 |

不把 D1/D7 直接写成“达不到 20% 就一定失败”。应该等有足够样本后参考 Roblox Creator Analytics 中同类游戏的回访与参与指标，结合自有留存趋势判断。

官方数据面板：<https://create.roblox.com/docs/production/analytics>。

## 22.5 A/B 试验优先顺序

| 实验 | A | B | 主要观察 |
|---|---|---|---|
| `EXP-01` 尸变过渡时长 | 3 秒公开过渡 | 5 秒公开过渡（V1.1 默认） | 新手理解、传播画面、留存 |
| `EXP-01b` 完整保密潜伏 | 公开过渡（V1.1 默认） | `IncubationSecret=true` | 仅在 Gate B 之后、通过引擎层泄密审计后进行 |
| `EXP-02` 断联倒计时 | 6 秒 | 8 秒 / 10 秒 | 连锁恢复、丧尸参与感、翻盘率 |
| `EXP-03` 扫描情报 | 目标 1/2-3/4+ 分级 | 只显示关键节点 | 策略水平与界面复杂度 |
| `EXP-04` 解药使用 | 近距离 2 秒读条 | 近距离 1.5 秒读条 | 治愈成功率、目标挫败感 |
| `EXP-05` 大局撤离阈值 | 24 人撤离 3 人 | 撤离 4/5 人 | 终局长度与双方胜率 |
| `EXP-06` 首个感染源 | 公开随机隔离突破（V1.1 默认） | NPC 自然追击 + 40 秒回落 | 开局速度与公平感 |
| `EXP-07` 中途加入 | §5.2 分时加入（V1.1 默认） | 隔离区等待下一局 | 中途加入者留存、对局公平感 |
| `EXP-08` 零号杠杆 | 倍率 1.5（V1.1 默认） | 倍率 1.0 | 枢纽出现率、断链参与率 |
| `EXP-09` 母巢指挥（§6.4） | 关闭（V1.1 默认） | 源头标记 + 母巢集结 | 人类胜率、遭遇间隔、标记转化率、树形状 |

# 28. “是否真的值得继续做”——立项与砍项目标准

## 28.1 不要被一次精彩录屏误导

核心玩法必须独立回答以下五个问题：

1. **没有复杂美术时，追逐与感染本身就好玩吗？**
2. **普通玩家是否理解“为何救 B 会影响 D、E”？**
3. **感染者在断联后能做出选择，而不是被 8 秒动画惩罚吗？**
4. **4 人、8 人、24 人三个规模，是否都能产生合理的胜负与节奏？**
5. **玩家玩完后，是否愿意自己发起下一局，而不是开发者求他们再玩？**

## 28.2 三种产品决策

| 结果 | 证据条件 | 决策 |
|---|---|---|
| `CONTINUE` | 玩家基本能看懂；多人局经常产生断链策略；再来一局意愿和实际回访改善 | 扩展内容、优化美术、测试商城 |
| `PIVOT` | 追逐好玩但断链常被忽视，或断链有趣但局内操作无聊 | 只重做弱项，限制改动 1～2 个核心变量 |
| `STOP` | 连续多个版本的真实试玩里玩家普遍不理解也不愿重复，或维护成本超过可承受预算 | 停止增加资产，把原型能力转化为后续项目积累 |

**决策不只靠内部主观评分，必须结合真实玩家录像、对局事件和下一次回访行为。**
